# 公共接口与内部实现

本页定义开发者应从哪里接入；不改变类型可见性，不新增稳定 ABI 承诺。C# 的 `public` 经常只是跨项目调用所需，不能据此认为所有类型都属于第三方 SDK。

| 分类 | 路径/入口 | 使用者与兼容要求 |
|---|---|---|
| 对外 .NET 接入面 | Pcl.Client：HostClient、LauncherSession、WorkspaceApi、公开操作服务 | 客户端；与匹配的 Contract 配套使用，连接时检查 Host 能力 |
| 对外数据及协议约定 | Pcl.Contract：请求、结果、事件、错误与能力；Host 暴露的 RPC | 所有客户端；新增字段考虑旧客户端，破坏性变更需协商和兼容验证 |
| 内部能力接口 | Pcl.Ports | 核心维护者实现/替换执行器；不是供客户端加载插件的 SPI |
| 内部业务实现 | Pcl.Application、Pcl.Domain、Pcl.Core、Pcl.Legacy、vendor | 核心维护者；不直接由客户端引用，不承诺这些类的二进制兼容 |
| 内部部署与传输实现 | Pcl.Host、SharedProtocol | Host 组合根、数据根所有权、RPC 分发；客户端实现线协议语义，不复制内部资源所有权 |
| 参考客户端实现 | Pcl.Desktop、Pcl.Native、Pcl.Desktop.Updates | 界面和特定平台部署；不是通用 Client SDK |
| 示例与诊断 | examples、tools/Pcl.CoreDiagnostics | 示例演示接入；诊断工具的直接 Core 调用不构成客户端接入许可 |

历史命名空间 `Pcl.Core.Contracts.*` 的类型实际编译在 **Pcl.Contract.dll**。判断依赖以 csproj 和程序集归属为准，不根据命名空间增加 Pcl.Core 引用。

## 客户端可以依赖什么

.NET 客户端使用 Client + Contract，经 Host 完成业务。新界面可以替换控件和布局；安装、兼容判断、凭据、文件提交和游戏进程留在 Host。SDK 为本地构建的 NuGet 包，版本以构建配置和生成包为准；没有 NuGet.org 发布或任意旧版永久兼容承诺。

非 .NET 客户端实现 [接入指南](客户端接入指南.md) 中的 NDJSON RPC v1、握手、请求关联和会话语义。workspace 名称由 WorkspaceApi 封装为 page 任务，不能任意当作顶层 RPC。具体字段以 Contract/实际分发为准。

## 扩展时怎样兼容

- 已有方法增加可选结果字段：保留旧字段及意义；客户端接受字段缺失并降级。示例是 SearchPage.Availability，旧 SourceStatus/HasErrors 继续保留。
- 新增操作或必需语义：同时设计能力标识、Host 暴露、客户端能力检查和不支持时的行为。不要为已有功能凭空假设一个能力字符串。
- 删除字段、改变含义、私有会话身份或数据格式：作为协调升级处理，明确最低兼容版本；修改 SDK 包号不能替代协议验证。
- 内部接口调整：可以连同调用方一起重构；保持对外行为并运行相关契约测试。Ports 当前不是独立版本化插件接口。

## 实验、平台与支持范围

“公共”表示预期接入面，不等于所有组合已稳定或已实机验证。跨语言 SDK、任意插件加载、各平台完整 GUI/游戏支持不能从 public 类型推断。以 hello 的实际能力、[支持范围](支持范围.md)及发布验收为准。

源码中的项目 README 标记本页分类；引用约束由 `scripts/check-module-boundaries.py` 检查。新增功能必须通过对应 Host 用例验证，不在客户端复制核心实现。完整实例见 [搜索来源状态](扩展示例-搜索来源状态.md)。
