# Plain Craft Launcher Refactoring 0.37

第三方基于 PCL 独立二次创作的内部开发版本。源码仍为私有，默认微软 OAuth client ID 为空；0.36.1 的署名、许可、启动前劝导与 Windows 蓝色主题规则继续保留。

## 实现

单项资源安装、批量更新和整合包文件安装均通过 ResourceDependencyPlanner 的多根入口进行联合规划：保留用户锁定版本，在私有目录试装候选，按实际 JAR 元数据与覆盖配置验证全套依赖，然后交回既有事务安装器提交。规划失败或取消不改动正在使用的模组目录；提交前检测实例资源与配置是否变化。

Fabric 新增 schema 0 与 schema 1 的明确区分，以及 config/fabric_loader_dependencies.json 的 version 1 覆盖规则。旧格式 requires/conflicts/recommends 分别映射为硬依赖、硬冲突和建议；不将旧格式的建议错误提升为必需前置。替换优先于删除和追加；追加的同名约束均须满足。版本数组为 OR，单条表达式中的比较为 AND；版本范围按 Fabric 语义解析。

整合包先以本地文件的哈希锁定根版本做离线规划，完整的包不要求远程查询。需要补齐前置时，按 Modrinth 文件哈希识别精确版本，保留包内实际文件与未发布的本地 JAR。多文件版本按查询哈希选文件，避免替换成不同的主文件。普通 ZIP/其他导入格式仍通过已有转换与整合包安装链路。

## 范围限制

这是有界候选搜索，不是任意 Fabric Loader SAT 求解器。远程自动补齐依赖依赖于资源目录声明，不能凭 mod ID 猜测任意商店项目；未发布前置、覆盖规则新增但目录未声明的前置需要用户提供，缺失时拒绝提交。完整包离线试装仍要求基础 Minecraft/加载器已可用。嵌套 JAR 多候选全局选择、运行时代码产生的依赖及原生库不在本轮完成范围内。

候选预算为 256 组，每个未锁定项目最多 64 个候选，待搜索组合最多 16384；显式根最多 512，远程图最多 1024。规划快照最多 8 GiB/100000 文件。超限会明确停止，不把预算耗尽当作无解。Iris 卸载仍拒绝依赖覆盖配置，本轮未扩大光影卸载范围。

## 本轮证据

- 已编译：Core/Domain/Application/测试项目，零警告零错误。
- 替身运行与真实文件事务：三入口一致性、配置变化、取消、哈希失败、共享依赖停用回滚；独立 Fabric Loader 0.19.5 Java 程序校验覆盖与旧格式语义。
- 平台实际运行：真实 HTTPS 下载 Continuity 与 Fabric API；单项安装、批量替换、缺少前置的受控 mrpack 安装完成，最终 JAR 哈希一致。
- 已编译：最终 Release Desktop/Host 及架构守卫通过；2784 个方法、43773 个成员使用，0 违规。新增/修改源码按嵌套层级换行，15 个文件的语法 token、注释和指令等价性验证通过。
- 定向验证：24 项新规划/官方 Loader 对照检查，63 项受影响复杂依赖兼容检查，22 项 Iris 保护与 38 项相关事务检查通过。HTTP 替身与真实文件事务不冒充真实网络。
- 账户边界：20 项启动劝导/幂等策略、7 项空 OAuth 配置检查，以及最终应用 15 项真实窗口交互通过。登录、皮肤服务的生产实现没有修改；未重新使用真实微软账号或实测皮肤网络服务，不携带原开发者应用标识或凭据。
- 平台实际运行：最终应用随包 Host 启动真实安装的 Fabric 整合包，进入独立 PCL037_World 副本；第一轮保存完成、退出码 0。第二个独立进程重新进入相同存档，重开前全部存档文件哈希一致；Host 正常退出后游戏继续运行。用户分别确认画面正常、标记和位置保留。
- 第二轮为独立进程，Host 退出后不再获取退出码，因此该项记录为 null；由进程消失与日志保存完成确认退出，不虚报为退出码 0。
- 测试脚本最初使用错误的日志字段名，随后又只匹配英文进世界文本；这些探针失败均未计为成功。实际通过记录为 final/game-first.json 与 final/game-reopen.json。

未增加矩阵子进度，不通过改状态将宽泛功能缺口关闭。详见后续本轮测试记录及原剩余清单。

## 复现方法与证据

从仓库根目录构建测试项目。`--planning037 <全新目录> <Java21可执行文件> <Fabric Loader 0.19.5.jar>` 调用官方 Java 实现，按13个版本样本比较六组元数据/覆盖的结果，并运行文件事务测试。`--live037 <全新隔离数据根>` 会实际下载 Minecraft 1.21.1、Fabric 0.19.5 和公开资源，先安装旧 Continuity，再批量更新，并构造只含锁定根的 mrpack，验证缺失 Fabric API 补齐及最终哈希。所需 Minecraft/Java 缓存可从合法现有安装复制，不能复制个人账户或原始存档来冒充隔离测试。

世界测试脚本为 `scripts/test-planning-037-game.py <app> <data> <output>`，第二轮加 `--detached`。按脚本限制准备 `verification-0.37/live-data`，在 PCL037-Pack 下放置可丢弃的 PCL037_World 副本。脚本会启动真实游戏并等待用户保存退出，最多15分钟；无人工结果时不得将其报告为视觉验收。

精选、去个人信息的结果在 [final证据目录](../artifacts/verification-0.37/final)。不包含游戏JAR、账号、存档、原始日志或本机进程命令行。真实测试使用 Apple Silicon macOS；Windows/Linux、Intel、任意整合包及长期稳定性未执行。

## 发布边界

最终扫描发现旧构建输出中两份 PDB 被 Host 通配复制带入应用；已在 Host 复制项排除调试符号，并在发布目录及复用的 app 目录再次清除 PDB 后签名。原生桥接的 LC_ID_DYLIB 保持 `@rpath/libpclwindow.dylib`。发布仍是 ad-hoc 签名、未 Developer ID 公证；源仓库仍私有。扫描覆盖已知个人路径、项目标识和令牌/私钥模式，不等于能识别所有未知秘密。

发布构建新增隐私门禁：若旧PDB、当前开发者home路径、运行时账户文件或令牌模式被带入，会直接使构建失败。用注入的假数据验证了拒绝路径；清理后的490个应用文件扫描无命中。最终Host/Core程序集与两次世界测试的文件哈希相同；Desktop仅在等价格式整理后发生字节变化，并已重跑最终包的15项窗口测试。
