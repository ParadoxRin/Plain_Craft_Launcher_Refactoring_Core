# Plain Craft Launcher Refactoring 0.38 · 嵌套依赖与验收

## 本轮实现

Fabric 的本地文件检查由“每个 ID 只取最高版本，同时检查所有嵌套包”改为有界候选图求解。顶层文件保持锁定；嵌套候选可以不选，必须有选中的父包；相同内容的嵌套 JAR 合并身份并保留多个父包。相同 ID/版本但内容不同的候选分别保留。depends、breaks、provides 唯一性、内置 ID 保留及环境禁用规则参与求解；不兼容的高版本不会遮住兼容低版本。

Domain 的 `FabricCandidateSolver` 不读文件或网络；Core 读取归档、覆盖配置及内置版本，通过 `FabricDependencySet` 组装输入。0.37 的单项、批量、整合包统一入口继续复用此检查，安装/启停失败仍使用已有回滚。不会改写模组内部 JAR，也不删除未选择的内嵌库，运行时仍由 Fabric Loader 做最终加载决定。

冲突通过有界 `DependencyDiagnostic` 契约从 Application 进入 page/game 操作快照、receipt、Client 和 Avalonia 任务窗口。包含模组/文件标签、版本范围、候选和关联约束，不序列化异常堆栈或宿主绝对路径。搜索预算耗尽独立标为 `DEPENDENCY_SEARCH_LIMIT`，不冒充无解。失败历史可以重新选择查看；启动预检使用同一诊断。

## 边界

这是硬约束可行性检查与确定性候选偏好，不是 Fabric 官方 SAT 优化器的逐行为复制。recommends/conflicts 提供警告，不承诺与官方可选模组软权重最优选择完全一致。顶层文件锁定比官方允许从重复根 ID 中择一更保守。冲突说明是有界关联证据，不承诺最小不可满足核。

候选上限2048（含内置项）、每ID最多64候选、最多100000子句/20000搜索节点/5000000次文字检查；归档递归深度8、单嵌套64MiB、每根展开256MiB。0.37远程目录规划预算继续有效。未声明的远程前置不会猜测下载。完整Quilt覆盖、自定义语言插件、任意第三方整合包仍未完成。不做矩阵子进度，也不将宽泛缺口直接改为完成。

## 语义来源与复现

以 [Fabric Loader 0.19.5 ModResolver](https://github.com/FabricMC/fabric-loader/blob/0.19.5/src/main/java/net/fabricmc/loader/impl/discovery/ModResolver.java)、[ModSolver](https://github.com/FabricMC/fabric-loader/blob/0.19.5/src/main/java/net/fabricmc/loader/impl/discovery/ModSolver.java) 和 [ModCandidateImpl](https://github.com/FabricMC/fabric-loader/blob/0.19.5/src/main/java/net/fabricmc/loader/impl/discovery/ModCandidateImpl.java) 为固定语义参考。产品使用独立实现，没有复制官方求解器代码。

`--nested038 <全新目录> <Java21> <Fabric Loader 0.19.5.jar>` 构造真实归档，通过反射调用原始签名JAR中的候选工厂，然后运行官方 `ModResolver.resolve`；不剥签名、不修改官方类。比对旧版本选择、无效可选副本、父子关系、同内容多父、同版本异内容、别名、内置ID、breaks、OR、循环、环境及回溯。安装三入口使用受控HTTP文件服务，并校验失败不改动实例。

`--live038 <全新隔离数据根>` 实际下载/安装Minecraft 1.21.1、Fabric 0.19.5、Continuity和Fabric API；受控包附加schema0及嵌套多版本纯元数据测试模组。可复制游戏/Java缓存，不复制个人账户与重要存档。

`scripts/test-nested-038-game.py <app> <data> <output>` 使用隔离 `verification-0.38/live-data` 中的 `PCL038-Pack/saves/PCL038_World` 副本；首轮托管，第二轮 `--detached`，验证游戏日志选中低版本、存档哈希及Host退出后游戏独立运行。只有用户明确反馈才能计为画面与标记验收。
