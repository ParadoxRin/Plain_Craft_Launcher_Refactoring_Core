# Plain Craft Launcher Refactoring 0.39 · Quilt依赖覆盖与验收

## 实现与设计

沿用 Host → 应用服务 → 统一资源规划 → Quilt 预检的安装路径，没有将规则移入 Desktop。`QuiltDependencyOverrides` 支持精确 ID、完整 ID 的 Java Pattern、顶层及嵌套归档路径；路径保留大小写，普通实例使用 `<mods>/name.jar`，嵌套为 `<mods>/outer.jar!/lib/child.jar`。路径覆盖先执行，再执行匹配的 ID/正则覆盖；路径允许唯一 ID 的模糊删除/替换，ID/正则使用完整依赖相等性。

重复路径最后一条生效；重复 ID/正则声明均参与。替换映射键后写覆盖，删除列表保留声明顺序和重复项。无序替换或重叠规则若可能产生不同有效约束，明确拒绝；不会捏造与实际 Loader 不一致的稳定顺序。被后续删除消除差异的替换可通过收敛检查。

`QuiltOverrideRuntime` 通过既有短命令 Port 调用实例 Java：Java Pattern 保留引用、内联选项、字符类交集等语义；Fabric 范围经过该实例真实 Quilt Loader 的 Fabric wrapper 转成 Quilt 约束，追加的覆盖使用 Quilt DSL。Fabric 模组的 group 为 `loader.fabric`。不改写 JAR，不加载模组代码；仅校验过的 Loader JAR 和自有桥接字节码进入 helper classpath。缺少 Java/Loader 时明确报错。

桥接资源目标 Java 8，附源码及 `scripts/build-quilt-compat.py <javac> <quilt-loader.jar> --check` 字节重现检查。每个进程64MiB堆、10秒超时，输入4MiB、正则512条/候选4096个；由短命令托管处理取消并清理临时目录。无序重叠检查最多12操作/4096状态，超限表示未判定，不是无解。

`version` 字段在对照的 Quilt 0.27.1/0.30.1 中只被解析，未应用到运行时元数据；本版接受字段但警告不改变版本。两个版本对不可能满足的 Fabric 范围不同：0.27.1拒绝，0.30.1忽略；桥接调用所选 Loader 的真实 wrapper，保留此差异。Quilt 的远程模组查询同时考虑 Fabric 候选，最终仍执行 Quilt 兼容性检查，不能由商店标签推定所有模组兼容。

## 来源与复现

固定实现：[QuiltOverrides](https://github.com/QuiltMC/quilt-loader/blob/0.30.1/src/main/java/org/quiltmc/loader/impl/metadata/qmj/QuiltOverrides.java)、[StandardQuiltPlugin](https://github.com/QuiltMC/quilt-loader/blob/0.30.1/src/main/java/org/quiltmc/loader/impl/plugin/quilt/StandardQuiltPlugin.java)、[FabricModMetadataWrapper](https://github.com/QuiltMC/quilt-loader/blob/0.30.1/src/main/java/org/quiltmc/loader/impl/metadata/qmj/FabricModMetadataWrapper.java)。另对照0.27.1同名类。产品未复制这些实现。[Quilt FAQ](https://quiltmc.org/en/about/faq/)说明Fabric兼容范围，[Modrinth版本API](https://docs.modrinth.com/api/operations/getprojectversions/)定义loader候选过滤。

测试程序集命令：`--quilt039 <全新目录> <Java21> <Quilt Loader.jar> <quilt-json5.jar>`。真实Java oracle读取同一夹具，并运行官方选择器及依赖变换；覆盖path、pattern、version、重复声明、depends/breaks、模糊匹配、Fabric转换和安装事务。`--live039 <隔离数据根>`实际安装1.21.1/Quilt0.30.1、Continuity/Fabric API，并经单项、批量和受控mrpack完成安装。测试纯元数据模组没有入口代码，故意声明缺失前置以验证覆盖确实参与预检和游戏加载。

## 仍有边界

不执行自定义 Quilt 插件；自定义虚拟/组合路径、任意多父嵌套路径身份和官方软偏好最优化仍未完成。未知Loader未来修改内部桥接API时明确失败，不静默使用近似语义。Fabric schema0在Quilt读取路径仍有限制。受控包不代表所有第三方包；原35项宽泛实现缺口未改状态，没有矩阵子进度。

登录、皮肤接口未改；发布继续为空OAuth配置。未读取个人钥匙串，未做真实微软/皮肤网络复测；Windows/Linux/Intel未执行。私有开发仓库、ad-hoc签名，未公证。

## 本轮失败与修正

首次oracle把集合和列表直接比较导致空集合误报，已改为语义集合对照。Fabric转换触发JArray空集合Concat复制异常，已修正枚举。官方0.27.1/0.30.1的空范围差异通过真实wrapper保留。测试归档时间戳造成内容相同但哈希不同，夹具已固定时间戳。

真实启动最初暴露测试元数据缺少intermediate_mappings，随后发现嵌套子包未被父包依赖而被跳过；夹具补全并强制依赖子包后，发现产品误删归档边界斜杠。产品现保留`!/`，新增缺少斜杠不匹配的负例，重新执行两版官方对照、三入口安装及真实游戏加载。失败轮次均未计为通过。

最终验收在外部报告完成，应用内附带的是生成该应用时的证据快照；不会为回填文字重新编译已测试的产品二进制。源代码及精选证据包包含最终记录。

应用ZIP解压签名、490个文件校验、433个产品载荷文件与游戏前哈希一致；LC_ID_DYLIB为`@rpath/libpclwindow.dylib`。源码及Git历史、应用ZIP（含AppleDouble元数据）和证据包均通过定向隐私扫描；扫描不构成对未知敏感模式的绝对保证。
