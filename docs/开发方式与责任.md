# AI 辅助开发方式与责任

本项目大量使用 AI 辅助编码。架构决策、功能取舍、边界判定与验收由人工负责；代码由 AI 生成并经人工审查。

AI 参与需求拆解、源码检索、实现与重构、测试探针、故障分析和文档整理。它可以执行被授权的构建、测试与发布流程，但不能自行改变需求边界、豁免许可、把替身测试写成实际运行，或把架构目标写成已完成。

人工负责确定产品方向、批准关键架构决策和兼容取舍，审查代码及来源，判断测试证据是否足以验收，并承担发布决策。游戏画面、交互和存档观察中的人工确认要具体记录，不能由自动化测试通过自动推导。

## 每次交付需要留下的记录

1. 变更解决什么问题、改动的真实入口、保留哪些行为。
2. 编译和测试命令、所用源码/包、成功与失败结果，以及未执行的边界。
3. 人工审查与验收的实际范围；缺少逐行审查或人工画面记录时明确写未记录，不补造签字。
4. 上游代码/数据来源、许可与修改说明；AI 生成不是原创性或可重新授权的证明。
5. 发布包哈希、隐私扫描的有限范围及剩余风险。

自动化可协助检查，不能替代责任归属。历史报告按原测试范围保留，新的工作方式声明不会追认所有历史提交已经逐行人工审查、全平台测试或具备完整兼容性。
