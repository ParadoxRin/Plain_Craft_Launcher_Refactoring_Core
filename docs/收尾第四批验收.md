# 收尾第四批验收：原生拖放、资源包与数据包世界行为

日期：2026-10-27。使用 0.40.1 后的本地 Debug 构建，在 Apple Silicon Mac 上完成；没有替换或发布 GitHub 安装包。脱敏结果见 [收尾第四批验收结果.json](收尾第四批验收结果.json)。

## 本轮范围及改动

补齐 UI-013、RES-012、RES-013 的定向验收。新增原生拖放观察探针、真实 Host 下载探针及游戏世界双进程测试脚本。复用现有页面、Host 安装和启动流程；没有为通过验收改写业务结果。本批没有发现新的产品故障。

探针初版两处编译错误（对 void 方法使用 await、访问契约中不存在的哈希字段）已修正，最终直接对导入文件计算哈希。这是测试代码修正，不计为产品功能修复。C# 嵌套表达式经格式化后再次编译成功，架构守卫零违规；保留原有两个 Bitmap.Save 警告及一个 Avalonia 构造函数警告。

## UI-013：真实 Finder 拖放

用户从 Finder 将自制 `PCL-Acceptance-Resources.zip` 拖入标题为“PCL — 拖放验收（隔离副本）”的真实 Avalonia 窗口，并点击“检查并导入”，反馈“完成”。探针只监听真实 DropEvent，不伪造事件或直接调用导入处理器；随后通过 Host 查询实际安装记录，校验导入文件与原 ZIP 的 SHA-1 相同。

本次验收覆盖单个资源包 ZIP 的原生拖放、确认和安装。历史 Host 分类与确认处理器证据保留；不外推为所有文件类型、多文件拖入及所有 macOS 版本均已人工测试。

## RES-012：真实下载、应用及游戏内材质

独立联网测试使用一个全新数据目录，通过 `workspace.browser.install` 下载 Modrinth 公开资源包 Lower Defaults (Shield & Fire)：project `xnKSRpXg`，version `p6IKJYJf`，108,030 字节，SHA-1 `10703768f153c8bb9479327ef68dd66ed88bfc37`。Host 独立获取版本元数据并执行原下载流程；最终文件与预先保存的公开元数据一致。通过 `workspace.browser.activate` 应用，确认 options.txt 持久化，Host 正常退出。该公开资源包本轮没有进入游戏验收；元数据列出兼容版本不等于实际游戏兼容。

游戏内验证使用自制的另一份资源包：资源格式 34、16×16 绿紫格金块材质及中文名称。格式号从 Minecraft 1.21.1 官方客户端 JAR 的 version.json 读取。Host 应用后，真实游戏资源管理器日志包含该 ZIP；用户放置金块并确认绿紫格材质正常。资源包和数据包的自制文件 SHA-256 与大小记录在结果 JSON 中。

历史应用撤销、外部改动保护测试仍作为历史证据，本批没有重新遍历所有撤销按钮。

## RES-013：按世界安装及实际行为

Host 将自制 `PCL-Acceptance-Data.zip` 安装到隔离的 `PCL_Acceptance` 世界，列举记录显示已启用。数据格式 48 同样来自官方客户端。数据包每次加载递增右侧 `PCL DATA OK / Loads` 计数，首次向测试玩家发放金块，并输出固定加载标记。

第一轮游戏日志证实加载函数执行；用户确认计分板、金块以及放置后的材质正常。第二个独立进程重进同一世界，用户对“标记、角色位置、材质、Loads 增加及退出游戏”的提问反馈“一切正常”。没有记录计数的具体数值，因此不编造从几增加到几。

真实公开数据包下载采用已有 TreeMiner 5.0.0 的历史证据（`artifacts/evidence-complete/pack-live-3/pack-live-result.json`，19,397 字节，SHA-1 `a9e9a1a63c70f5cefc7bbf333c286a872e70896f`），本次核对了记录存在，但没有重跑它。世界行为证据属于自制包，不声称 TreeMiner 在本轮进入世界。

## 保存、独立重进及 Host 生命周期

使用原测试世界的独立副本，没有打开用户重要存档。第一轮通过 Host 托管游戏，保存完成并退出，退出码为 0。第一轮保存后的 48 个存档文件与第二轮启动前逐项 SHA-256 一致（不计 session.lock）。

第二轮进入同一世界后，Host 正常退出，游戏在其退出后仍持续运行；用户确认标记、位置、材质与计数，然后退出整个游戏。日志包含保存完成记录，游戏进程结束。第二轮为独立运行模式，无法从已退出的 Host 获取游戏退出码，结果明确保留 null，不标成退出码 0。两轮均验证启动幂等键重试返回同一个 operationId。

两轮之后，资源包与数据包 ZIP 的大小及 SHA-256 仍与输入一致。原始日志、玩家文件名、进程 ID 和本机绝对路径留在忽略目录 `artifacts/closeout-fourth/`，不写入脱敏报告。

## 复现入口与限制

- `src/Pcl.Desktop/DropWorldAcceptance.cs`：显式参数 `--drop-world-acceptance --acceptance-report <report> --acceptance-files <fixtures>`，同时必须使用独立 `--data-root`；需要真实 Finder 拖放和确认。
- `scripts/test-resource-data-world.py <dotnet> <host-dll> <data> <output> [--detached]`：仅允许名为 `closeout-fourth/game-data` 的预置隔离根。先复制可丢弃世界、准备 Java/客户端和上述两份包，再分别运行托管及独立模式；需要用户观察、保存和退出。
- `scripts/test-resource-download-host.py <dotnet> <host-dll> <public-version-json> <output>`：输出目录中的 download-data 必须不存在；真实联网安装、哈希核对与应用，不启动游戏。

本轮使用隔离的离线测试身份，不读取真实账户或钥匙串；未复测微软登录及皮肤。不将上述三个限定验收扩展为任意加载器、版本、资源包或数据包兼容，也不扩大到全项目回归。
