# PCL Mac 0.25：架构实现与验收

本版本继续保留完整的现有 Avalonia 界面与功能，实施真实程序集隔离。它不是“所有 PCL2 功能已完成”的声明。旧的 0.23/0.24 发布包保留。

## 已接线并编译的边界

```text
Client        -> Contract
Contract      -> 标准库
Domain        -> 标准库
Ports         -> Domain
Application   -> Contract + Domain + Ports
Host          -> Application + Core（执行桥/Adapters）+ Contract
Desktop       -> Client + Contract
                 + Core/Application（旧页面/Bootstrap 过渡例外）
```

Contract、Domain、Ports、Application 均为独立项目。Client 禁用传递项目引用并仅显式引用 Contract；构建守卫同时检查实际程序集引用，不能靠改 csproj 或命名空间伪装隔离。只引用 Client 的故障消费者构造 `MinecraftService` 会编译失败。

- Contract 包含安装、操作、账户、Host、游戏 DTO 及接口；保持既有公开命名空间与 JSON 格式，Core 为已迁移公共类型提供转发。
- Domain 已承接版本标识、进度值、加权布尔约束求解、Quilt 和 Maven 版本比较；无 Ports/Core/网络/磁盘依赖。Quilt JSON/TOML/ZIP 解析仍在 Core。
- Ports 独立保留 `IAccountSecrets`、长短进程、操作存储、安装执行和日志边界；没有更改钥匙串名称或存储作用域。
- Application 包含操作受理、幂等、取消、快照、receipt 恢复、统一启动受理及安装等待门面；不依赖旧 Core。账户 HTTP 编排和 Java/游戏准备执行桥仍在旧 Core，未冒充全部迁移完毕。
- 远程 `LauncherSession`、安装等待适配及托管游戏观察已移入 Client。Avalonia 通过 `IGameSession` 借用会话，不再使用 Core 的 ProcessSpec/进程 Port 托管远程游戏。
- 分帧算法由单一内部源文件在两侧传输实现中编译；没有把流 I/O 塞进 Contract 或新增 Shared 值类型程序集。

## 本次修复

1. 原 Host 为每个连接保留最多 65,536 个请求 ID，长时间游戏轮询可触及上限。新 Client 在发送锁内分配连接随机前缀与连续序号，Host 以常数空间拒绝重放、跳号及换前缀；旧请求格式保留有界兼容。测试实际受理 100,001 个 ID，不把它当作数小时游戏验收。
2. Client 严格验证响应协议版本。读取通道结束后，新请求立即失败，不再进入无人处理的永久等待。
3. stderr 按块脱敏无法保证跨块令牌安全；Client 只保留受控诊断标记，原文不进入日志缓存，业务错误仍通过结构化错误码返回。
4. 网络设置交接保留下载服务对象，只在无活动下载时替换 Handler，避免旧页面借用已释放下载器。使用真实本地 HTTP 下载校验此路径。
5. 资源项目详情错误地返回数组时明确拒绝。原 5 项夹具未分别模拟“项目详情”和“版本列表”新增请求，现修复响应路由并保留依赖、过滤与手动恢复断言；新增畸形响应拒绝用例。
6. 续做界面测试仅匹配本次新操作，不再把旧历史的多个子尝试当作重复数据。
