## 发现与处理

第一次登录已通过正版权益与档案，但立即刷新返回 `invalid_grant` 类错误。原逻辑隐藏了微软细分错误码，且 CLI 在刷新成功前不保存首次登录结果，导致排查必须重新授权。

本轮增加数字错误码白名单提取：仅显示 `error_codes` 的受限数字或 `AADSTS` 数字，不显示错误描述、令牌、邮箱和请求内容。新增回归覆盖正常错误码、混入文本、负数及描述回退，保留重新登录异常类型和禁止离线降级的行为。CLI 按显式 `--remember` 先保存已验证凭据，并单独记录首次登录成功，再执行刷新验收；增加 `account-verify` 复测钥匙串冷启动。

重新授权后的即时刷新、独立进程刷新与桌面冷启动均成功。第一次失败没有重现，根因尚未确定；不声称已经修复微软服务端的偶发拒绝，也不绕过正版检查。

## 证据与边界

本地证据在 `artifacts/verification-0.16/`：`microsoft-login-result.json`、`microsoft-cold-refresh-0.16.json`、`desktop-manual-launch.json`、`user-world-acceptance.json`、`final-tests/test-results.json`。世界画面和存档来自用户明确确认；自动日志证据只证明程序启动、图形初始化及正常退出。

本轮为一个真实正版账户、原版 1.21.1。多微软账户切换、真人退出后重新授权、Realms 联机及其他 Minecraft 版本的正版流程未在本轮逐项验证。既有加载器和版本兼容结果保留原证据范围。无需账号的下载和安装继续开放。

访问令牌只在内存中使用；刷新令牌按用户的记住登录选择存入 macOS 钥匙串。发布包、源码包不包含账户索引、令牌、用户世界或游戏文件。自有代码继续逐层换行并保留功能说明；注释及格式化工具的当前报告写入独立目录，避免覆盖历史版本报告。

应用使用本地 ad-hoc 签名，尚未获得 Apple Developer ID 公证。旧版 0.15 应用与源码归档保留。
