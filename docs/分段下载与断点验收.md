# 0.8 可选分段下载与断点验收

分段下载默认关闭。“任务与诊断 → 网络 → 大文件分段下载”可启用，并配置每个文件 2–8 个分段工作线程，默认 4。只有已知大小、至少 32 MiB 且具有完整 SHA1/SHA256/SHA512 校验值的 HTTP(S) 文件才进入分段流程。未知大小、无哈希、小文件继续走既有顺序下载。1.21.1 客户端约 26.8 MB，不符合该阈值。

实现位于 `SegmentedDownload.cs`，由 `DownloadService` 在既有同目标互斥、任务队列、暂停与总限速内部调用，未递归调用下载入口。4 MiB 完整块由空闲工作线程动态领取；各下载共享最多 16 个分段 HTTP 请求，同时受每文件配置约束。线程数上限不是对下载提速幅度的保证。

先发送 `Range: bytes=0-0`，只接受 206、准确起止位置/总长度、适当长度与 identity 编码。每个块重复检查 Content-Range、声明长度与实际字节数；若强 ETag 可用则以 If-Range 绑定。服务器忽略 Range、返回错误范围或分段内容整体校验失败时回退顺序下载。各读取环节调用共享限速与暂停逻辑，取消可停止等待及网络读取。

分块位于目标旁的 `.segments/<size+hash+blockSize fingerprint>/`。只复用完整块；每个块都有自己的 SHA256/起点/长度收据，重启后重新校验本地文件再跳过下载。未完成块重新下载，不把任意 `.part` 长度视为完成证据。内容身份绑定官方整体哈希；本地块校验不代替最终来源校验。合并写入单独临时文件，整体大小与哈希全部通过后才原子替换目标，失败和取消不覆盖原有目标。

目标、`.part`、分块目录、每个块/收据/合并文件仍经过路径检查，包含 dangling symlink。不会退化既有目标链接保护。断点目录可能在取消后保留供重试；完成时清理已知块文件。程序被强制结束时，只恢复有完整收据且重新验证通过的块。没有承诺恢复未完成块的内部字节位置。
