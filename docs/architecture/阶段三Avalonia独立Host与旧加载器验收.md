# 阶段三：Avalonia 接入独立 Host 与旧加载器恢复

依据：`PCL-Mac架构规范.md` v1.2。本批为阶段三的可运行增量；未将整个软件或全部页面宣称为已完成迁移。

## 1. 默认运行路径

默认 Avalonia 启动过程异步建立 `RemoteComposition`，启动独立 `Pcl.Host`、协商私有协议，再创建主窗口。`--in-process` 仅保留显式开发兼容路径。主安装按钮、版本管理安装、任务中心取消/续做通过 Contract → Client → Host 复用既有安装 runner；安装过的原版也由远程安装流程校验。正式启动按钮通过统一 `IGameLaunchOperations` 受理，UI 不提交令牌、Java 路径或完整命令行。

自包含应用包含独立的 arm64 Host、运行时、原生窗口桥与既有 LWJGL agent。正常运行优先执行包内 Host apphost，无需本机 SDK。构建和发布目标都复制 Host，不依赖开发目录。组合根不是全局单例，没有引入 DI 容器。

## 2. 尚未迁移页面的排他交接

旧的模组、整合包、设置、外置认证等页面仍借用原有 Core 服务。为保留功能，它们在此增量中受显式兼容写入授权保护：

- OS `.launcher.lock` 始终由 Host 持有，GUI 不另抢一把根锁。
- `desktop.acquire` 只在无安装/启动准备、认证任务和运行游戏时授予一个不透明授权；不是 TTL、PID 或心跳夺权。
- GUI 归还授权后，Host 重读账户索引、下载历史和网络选项，才受理安装、认证或启动。持有授权时 Host 拒绝新的这些写请求。
- Host 工作时关闭旧页面的写入口，任务中心只允许查询/取消；旧窗口关闭时不再用过时缓存 Flush 覆盖 Host 记录。选中实例、选中账户的附带保存也遵守授权。
- 工作达到真实终态，或托管游戏退出后，GUI 才重新取得授权，重读公开索引与历史。父进程生命周期日志写临时目录；归还授权时停止父进程的根目录诊断写入。
- EOF 时 Host 收回逻辑授权；已有安装继续排空，托管游戏继续观察，根 OS 锁覆盖全部收尾。没有按 PID 接管旧进程。

这是受约束的过渡边界，不能当作“所有辅助窗口已经成为纯 RPC Shell”。以后逐页迁移后才能删除兼容授权和父进程的旧核心借用。

## 3. 登录及外观

微软登录、令牌刷新、正版验证、微软皮肤/披风操作在 Host 内执行。沿用 `IAccountSecrets` 和原数据目录计算的钥匙串 service 名；未更名或搬迁凭据。UI 仅接收公开账户索引、会话可用性、短时 user_code/验证网址，不接收 DeviceCode 或访问/刷新令牌。

登录任务先持久化受理，再由被 Host 字典持有并在关闭时观察的任务执行。取消明确发送命令、等待终态；Task 与 CTS 都有唯一关闭责任。登录记录不保存授权提示或令牌；Host 重启将未完成登录标记中断，终态同键不会重新授权，不同 remember 参数同键拒绝。

不记住登录的会话留在同一 Host 内存中，临时借还旧页面授权只重读索引，不销毁会话。退出/移除微软账户经 Host 清除缓存及相应凭据。皮肤网络操作也使用 Host 持有的任务和显式取消，避免系统钥匙串或 HTTP 同步前段堵塞协议读取。皮肤修改不在断线后自动重放；取消本地请求不承诺撤销远端已经接受的修改。本轮没有修改真实用户的皮肤/披风。

## 4. 游戏与退出

Host 托管真实进程；桌面使用逻辑句柄查询、停止及只读日志桥，不创建第二个 Java 进程。日志 reader 保留预读缓冲，有限速展示；协议断连时也会结束观察，避免永远等待。

托管游戏运行期间，关主窗口仍为隐藏；游戏结束后按原策略显示或关闭。独立运行模式先由 Host 创建 detached 游戏，随后 UI 与 Host 正常退出，游戏继续运行。正常退出先取消活动操作并等待 UI finally，五秒预算超时不提前释放活跃依赖。旧核心借用对象释放时不再 Flush 数据目录；Host 按原顺序排空并单次释放其服务，根锁最后释放。
