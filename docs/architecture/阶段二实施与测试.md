# 阶段二：凭据与进程边界实施记录

日期：2026-10-25（Australia/Sydney）。基线：[架构规范 v1.2](PCL-Mac架构规范.md)。

本轮保留 Avalonia、既有登录策略与安装链，不引入 RPC、SwiftUI 或新的后台任务系统。以下“实际运行”仅指本轮有记录的执行，不追认其他功能或历史测试。

## 1. 凭据接线

`IAccountSecrets` 定义移至 `Pcl.Core/Ports/Credentials`，保留 `Pcl.Core` 命名空间及同步 `Get/Set/Delete` 签名。`AccountManager` 继续只依赖该接口，账户索引、离线身份、缓存、刷新及注销规则未重写。

原 Security.framework 实现移至 `Adapters/Mac/KeychainAccountSecrets`。原 `MacAccountSecrets` 留作转发兼容门面。以下存储身份保持原样：

- `local.pcl.macport.oauth.` 加数据目录绝对路径 SHA-256 前 20 位十六进制；不改目录大小写。
- `kSecAttrService` 与 `kSecAttrAccount` 的查询方式、原账户 ID 和条目类型。
- 原生 API 直接传值，不把令牌放进 shell、参数或普通文件。

桌面组合根构造 Adapter 与 AccountManager 后注入窗口；窗口不再自行选择凭据实现。CLI 的持久凭据实现也切换到该 Adapter。旧测试入口仍可使用兼容门面。

同步接口保持兼容，现有同步账户保存／删除入口的调度方式未在本轮重写；这不是完整账户 Application Contract 的迁移，也不声称已经消除全部 UI 同步原生调用。后续账户应用入口应统一调度并串行管理账户状态，不能用无持有者的 Task.Run 包装来假装完成。

## 2. 短命令与游戏长进程

| 边界 | 实际行为 | 已接调用 |
|---|---|---|
| `IShellCommandRunner` | 参数列表启动、双流并发排空、异步等待退出、取消后回收拥有的进程树与输出 | Java 检测、Forge/NeoForge 安装器、OptiFine 补丁、等待型启动前命令、EasyTier 节点查询 |
| `IGameProcessHost` | 启动即返回逻辑句柄；独立等待、日志读取、显式终止与释放；Dispose 不杀活跃游戏 | LaunchService 的托管与独立运行，Avalonia 与 CLI 正式启动入口 |

`RunningGame` 不再暴露 `System.Diagnostics.Process`。调用方使用逻辑 ID、Pid（仅展示）、退出任务及 StopAsync/DisposeAsync；Adapter 内保留最初创建的 Process，不接受任意 PID 重新接管。

取消 WaitForExitAsync 只停止该次等待，显式 TerminateAsync 才停止游戏。Unix 温和停止发 SIGTERM，强制停止保留原 Kill(entireProcessTree: true) 行为；不声称实现了系统级 job object 或完整后代进程隔离。

保留旧同步 LaunchService.Start/StartDetached 转发入口以兼容旧调用；正式 UI/CLI 使用异步入口。MinecraftService 的旧默认构造路径保留真实 Adapter 默认值，ForVersion 借用同一组 Port。它们是本轮明确保留的旧核心兼容接线，不是最终“核心完全不引用 Adapter”的状态；桌面正式路径由 Bootstrap 显式注入。

音乐、EasyTier 守护进程、非等待型启动前辅助程序仍按各自既有生命周期管理，未冒充已经统一为游戏 Port。

## 3. 日志、资源与退出

托管输出单行最多 65,536 个字符，超长行整体省略并标记；短命令每条流最多保存 1,048,576 个 UTF-16 字符。已知敏感值在发往订阅者和保存前替换。ProcessSpec 用普通 class，避免 record 的自动 ToString 输出参数。

游戏订阅队列最多 256 条，慢消费者可能丢弃较早条目，Sequence 可见间隙；文件独立写入，达到 16 MiB 后标记截断。文件写入失败不阻塞管道排空，并发出诊断。单句柄只承诺一个日志消费者。此实现不是阶段三完整 operation.log 契约。

独立模式保留固定 `/bin/sh` 脚本加 ArgumentList、直接追加游戏日志文件的旧行为。用户参数不拼入脚本；启动器退出后游戏没有依赖其存活的输出管道。独立模式不提供托管订阅／重新接管；直接文件日志也没有托管逐行脱敏与大小上限，不宣称已有统一受控日志服务。

桌面组合根唯一拥有共享 MinecraftService 和游戏 Host，按 minecraft → game-processes → root-lock 顺序释放。版本服务只借用共享 Host。托管游戏存活时关闭主窗口保留作用域；close 策略先脱离再退出，Host 释放不杀游戏。原界面可见性策略保持原有分支。

## 5. 构建与状态

Desktop 与 CLI 的必要构建结果以日志为准；已知 MainWindow 使用组合根注入构造，Avalonia 仍会给 AVLN3001 警告，实际窗口流程已运行。不得用重新添加自行组装服务的无参构造来消除此警告。

新增源码已按现有嵌套换行格式整理。既有 0.23 发布包保持原样，本轮是架构实现与验证，没有把历史安装包冒充新版。

阶段二这两条边界已接线、已编译，并有 Apple Silicon macOS 实际运行证据；完整账户 Contract、所有辅助进程收口、进程外 Host 和恢复协议仍是后续工作。
