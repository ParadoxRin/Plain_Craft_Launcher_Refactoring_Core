# 阶段三首批：操作模型、持久化与原版安全续做

日期：2026-10-25（Australia/Sydney）。基线：[架构规范 v1.2](PCL-Mac架构规范.md)。

本批实现同进程操作模型，并把现有 Avalonia 安装入口接入。尚未引入独立 stdio Host，不声明完整阶段三、RPC、operation.log 或受控资源分块协议已经完成。

## 1. 实际调用链与所有权

```text
Avalonia 安装按钮／版本选择
  -> IVersionInstallService（明确保留的 v1 等待兼容器）
  -> IVersionInstallOperations（新 v3 操作契约）
  -> InstallOperationService（受理、状态、取消、持有 worker）
  -> IOperationInstaller
  -> ExistingVersionInstaller
  -> 既有 MinecraftService／VersionInstaller／DownloadService／JavaService

Bootstrap
  -> .launcher.lock
  -> FileOperationStore（.operations.lock）
  -> InstallOperationService
  -> 退出：worker 与 UI 排空 -> operation-store -> minecraft -> game-processes -> root-lock
```

任务中心“操作与恢复”页直接调用 v3 Contract 查询、取消和续做。旧安装历史仍从 `install-operations.json` 读取；旧记录重试创建新意图，不覆盖历史 taskId。没有静默将旧历史伪装成带有可信 receipt 的新操作。

Ports 不依赖 Contract 或 Application：存储 Port 读写版本化字节记录，内部安装 Port 使用独立输入／结果／receipt 数据；Application 负责映射 DTO 和定义 StoredOperation 的业务状态。

旧等待接口不冒充已升级为立即返回 operationId。它明确桥接 v3，维持现有按钮的进度和取消交互；其后台 CTS 仍属于 runner，界面的取消意图通过 CancelAsync 转发。

## 2. 受理与幂等

受理只执行本地参数校验、去重、受理记录落盘和入队，不等待元数据、依赖求解或下载。`queued` 不等于安装成功。后台 worker 的 Task 由服务字段持有，退出时等待；没有无人持有的 Task.Run。

新契约：AcceptAsync / GetAsync / ListAsync / CancelAsync / WaitAsync。返回稳定 operationId、状态、stage、Sequence 水位和安全错误码。未知进度总量为 null，不伪造百分比。

当前命令空间只有 `version.install`：键作用域是当前数据目录的安装操作存储，fingerprint 包含命令类型、游戏版本、加载器、显式目标平台及 resumeOfOperationId。未来增加其他命令必须扩展复合键命名空间，不得直接共用当前键字典。

- 同键同参数返回原 operationId，包括重启后的终态，不重新执行。
- 同键不同参数返回 IDEMPOTENCY_CONFLICT。
- 新尝试使用新键，续做关联 resumeOfOperationId，旧终态保留。
- 数据目录之间相同键相互独立；宿主 OS 版本升级不阻止旧记录查询或原请求去重。
- 保留策略：当前记录和键不自动过期或淘汰；达到 4,096 条拒绝新受理，返回 OPERATION_RETENTION_LIMIT。后续归档／清理必须另定兼容语义。

旧安装链共享元数据、索引和缓存，本批采用目录内单 worker 串行执行，最多 16 个非终态操作。尚未把所有旧修复、删除、模组变更、CLI 直接安装入口纳入统一操作锁；不能声称这些入口已具备跨用例事务隔离。任务中心续做沿用主窗口忙碌协调，避免新增 UI 入口并发绕开已有交互约束。

## 3. 持久化与快照

每个操作使用 `operations-v3/op-<GUID>.json`，外层 FormatVersion=1。幂等键、fingerprint、状态及 receipt 放在同一原子文档中；不会先响应受理再补键映射。

写入过程：同目录临时文件 -> 写入完整 JSON -> Flush(true) -> 原子替换 -> Unix 同步目录项，完成后才确认受理。每条记录最多 16 MiB。macOS 实际运行已验证此路径；Windows 的目录同步尚未实现和验证，不将本机结果扩展为 Windows 掉电持久性保证。

查询只返回已落盘的快照水位。进度合并到最多每 250ms 落盘一次，checkpoint、cancelling 和终态立即落盘。中断后不从内存猜进度。当前只提供查询／等待，不提供事件订阅，所以本批不声称已实现事件缓冲衔接、重放或背压。

损坏格式、非法身份或链接路径会拒绝读取／启动并保留文件，不自动清空历史。`.tmp` 不是事实来源。目录同步也不等于已用断电实验验证了底层存储设备的全部持久性。

## 4. 取消、退出和崩溃

- 请求等待取消只停止该次等待，不取消已受理操作。明确的 CancelAsync 先持久化 cancelling，再异步发送后台取消信号。
- 取消回调不在状态锁内同步执行；信号 Task 有所有者，退出时排空。回调失败由 runner 观察，操作终态仍由安装器实际退出决定。
- 排队操作收到取消后不进入安装器。正在执行的任务停止后才报告 cancelled。
- Java 准备在原版安装标识提交前完成。进入提交后不再因为迟到取消改报 cancelled；实际成功保留 succeeded。
- 正常退出停止受理、请求取消、等待 worker 与界面 finally，再释放存储及共享服务。组合根仍使用五秒等待预算；超时不提前释放任务依赖。
- 系统零预算退出路径保留运行期间已落盘记录，不伪造终态。崩溃后只有新独占持有者将 queued/running/cancelling 转为 interrupted。
- 存储故障返回 STORE_UNAVAILABLE，不伪造已持久化成功。若任务已受理但无法写终态，保留非终态恢复证据；即使取消状态写入失败，退出仍向拥有的工作发出停止信号并等待清理。

同进程应用进程结束时，安装不会继续后台存活；视图关闭和应用退出是不同路径。任务中心视图关闭不取消已受理续做任务；独立游戏进程策略仍沿用阶段二实现。

## 5. receipt 与安全续做范围

本批完整安全续做覆盖原版。receipt 包含格式版本、操作／实例身份、游戏／加载器、目标平台、官方版本元数据 SHA-1、资源索引 SHA-1、确定排序的计划摘要、相对路径／大小／SHA-1 文件清单和提交阶段。

续做不是从旧列表直接下载：

1. 只接受旧 cancelled/failed/interrupted 操作的新尝试，父 receipt 的操作身份和请求必须匹配。
2. 校验 receipt 的结构、目标、相对路径、哈希格式和阶段；拒绝越界路径、绝对路径和符号链接。
3. 重新获取版本清单，以可信元数据哈希校验原始版本 JSON 和资源索引，重新生成当前平台计划。
4. 元数据哈希、计划摘要或文件清单变化时返回 RESUME_PLAN_CHANGED；旧计划不能冒充同名版本的当前计划。
5. 已有文件继续由原下载器逐项校验大小和 SHA-1。损坏文件及 .part 不因“存在”而被信任；缺失／损坏内容重新下载并校验。
6. Java 继续使用既有平台和完整性检查，不恢复 Java 安装器的任意中间内存状态。
7. 准备和可取消步骤完成后发布安装标识，再完成实例可见性收尾并写真实终态。没有整目录长事务，也没有宣称完整多文件回滚。

本批 receipt 阶段包括 planned、verified、files-committing、files-ready、committing、committed；`files-ready` 与整个操作终态不同。文件缓存复用是经过可信新计划校验的复用，不是恢复原下载连接的承诺。

其他加载器可通过新操作模型完整安装，但没有可靠外部安装器 receipt 时不允许带 resumeOfOperationId 续做，返回 RESUME_UNSUPPORTED。应以新键重新完整执行相关安装器，不能称为 Forge/NeoForge/Quilt 任意步骤断点恢复。没有 receipt 的旧历史记录同样只能发起新尝试。

游戏证据止于图形／材质初始化及测试进程清理。本轮没有人工视觉验收，没有进入世界、保存／重进或微软再次授权，没有 Windows/Linux 实际执行，也没有全量功能回归。

初轮测试曾发现新目录创建缺失，以及测试设置／UI 控件选择方式的问题，均已修正并保留早期日志；成功数量以最终报告为准，不把失败尝试计入通过数。
