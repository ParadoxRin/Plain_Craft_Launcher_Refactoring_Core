## 收尾目标

用户将本项目定位为允许开发者自定义启动器的底层平台；后续界面交给其他开发者。现有 Avalonia 是参考客户端，未来 SwiftUI、Windows 和 Linux 原生客户端尚未实现。Desktop 与 Core 的隔离已经落实，但它并不证明 Windows/Linux 宿主适配器已经实际运行。

当前已有 Contract、Client、独立 Host、Application、Domain、Ports 与 Core 适配实现。登录凭据经 IAccountSecrets 隔离；安装、资源、实例管理在 Host 执行；现有窗口生命周期与游戏独立运行有历史限定证据。不能将这些扩大成稳定公共 SDK、第三方插件系统或三平台发行版的完成声明。

本轮不取消原矩阵条目、不新增子进度、不自动把高级功能移出范围。下面的优先级是收尾建议；是否将某项留到后续版本需要单独确定。

## 三种状态究竟表示什么

- **部分实现**：包含真的代码缺口，也包含有限版本支持和缺少某类实测；47 个标签不等于 47 个独立缺陷。依赖求解的同一缺口会影响 RES-007、RES-015、RES-016 和 PACK-002 四个入口，不能按四套算法估工作量。
- **未实现**：AUTH-009 统一通行证专属预设／协议，UI-008 自动更新。外置 Yggdrasil 不等于统一通行证；发布 GitHub ZIP 不等于安全自动更新。
- **待验收**：已有代码和部分证据，仍缺指定的页面、游戏、平台或外部条件验证。测试夹具通过、图形初始化、世界保存重进是不同层次，不能互相替代。

## 从平台角度建议如何取舍

### 收尾优先

1. 无账号的 Host/API、实例、设置、导出与安全边界验收；把调用示例、错误码、取消和恢复语义交给后续 UI 开发者。
2. NET-011：资源／整合包任务在 Host 中断后的恢复策略。现有未知提交拒绝重放是保护措施，尚不是所有任务自动续做。
3. NET-012：统一代理覆盖；当前文件下载与元数据请求并未全部共用同一策略。
4. 依赖与包格式的支持边界：明确支持与拒绝的输入，保证不可判定时不破坏实例；不以“支持任意包”为交接承诺。
5. 交接最低条件：从干净源码构建、无 Core 引用的最小客户端示例、实际 Host 端到端链路、凭据不泄漏、退出与游戏独立运行。现有证据需要逐项关联，不能只凭分层图验收。

### 可交给后续扩展开发者，尚未取消

3D 皮肤预览、全量 WPF/XAML 兼容、原版公告、界面细节、三平台原生 UI；自动更新需要各发行者自己的更新源、签名和应用替换策略。动态分片、任意 Quilt 插件／虚拟路径、完整历史加载器语义、任意整合包三方语义合并也不应成为“基础框架可交接”的无限验收目标，但现有缺口仍保留。

外置账户游戏启动是真实缺口，若平台宣传外置认证完整支持则必须补齐；若暂不做，应明确只有配置和协议部分、执行器拒绝启动。统一通行证、原 PCL 节点互通、CurseForge 和双真人账户验证涉及外部条件，不假装通过。

  --closeout-local artifacts/closeout-repeat/local-data artifacts/closeout-repeat/local.json
