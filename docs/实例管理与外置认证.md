# 实例管理与外置认证（0.8 开发增量）

本记录对应 `InstanceManager`、`LauncherSettingsStore`、`InstanceWorkspace`、`ExternalAuthentication` 与 `AccountToolsWindow`。功能已接入业务服务，验收状态以本轮测试回执为准。

## 实例管理

- 首页入口打开独立实例管理窗口，可搜索名称/版本/ID，组合加载器与收藏/隐藏分类，重命名、描述、收藏、隐藏和恢复显示。
- PNG/JPEG 实例图标可导入与恢复默认。输入不超过 4 MiB、2048×2048 像素，检查后由 GUI 解码并重编码为实例内 PNG；复制、备份带着走，普通整合包导入只将其视为被动文件。
- 启动参数统一写入数据目录 `launch-settings.json`，全局设置与实例覆盖分别持久化。实例选择“使用全局设置”后恢复继承；覆盖为完整设置快照。
- 内存、窗口尺寸、全屏、Java 路径、附加 JVM/游戏参数、服务器地址均进入真实启动计划。参数通过 `ArgumentList` 传递，不经 shell；现代版本使用元数据的 Quick Play 字段，旧版使用服务器/端口参数。
- 指定 Java 通过真实 `java -version` 与架构检查，主版本/架构不符时阻止启动。
- 可扫描启动器已安装 Java、系统/用户 JDK 目录、Homebrew 和 JAVA_HOME，真实检查后按当前架构与版本排序供选择；跳过会触发安装弹窗的 `/usr/bin/java`。
- 目录导入支持本启动器实例和含完整原版元数据的游戏目录；用户数据复制到独立实例，原目录保留。第三方继承版本会提示未解析原因，需走整合包导入或重新安装加载器。下载来源重新按官方清单/已有校验值验证。
- 复制、ZIP 备份保留存档与模组，排除启动器账户文件；共享资源不重复复制。恢复备份会创建新实例，并清空导入的 Java 路径、附加参数和自动服务器地址，避免激活备份中的执行配置。
- 删除私有实例使用本地回收站，可恢复全部目录；使用共享游戏目录的默认实例只移除列表记录，保留存档与共享文件，避免破坏其他实例。
- 修复补全官方父版及可下载的加载器依赖；缺失的安装器生成文件明确要求重新运行加载器安装器。
- 可导出 `.command` 离线启动脚本，参数逐项 POSIX 引号转义，不导出微软或外置账户令牌。

仍需补齐：多个外部游戏目录的原地注册/切换、逐字段继承覆盖、自定义 GC 方案、任意第三方继承链导入、跨设备完整离线备份恢复，以及安装器生成文件的自动重建。备份恢复当前需要官方父版可用，必要时联网补全；启动前命令已由独立模块接入，其信任与验收另见功能矩阵。

## 外置认证与皮肤

实现依据为 authlib-injector 官方[启动器规范](https://yushijinhun.github.io/authlib-injector/en/launcher-technical-specification.html)、[服务端协议](https://yushijinhun.github.io/authlib-injector/en/yggdrasil-server-technical-specification.html)与[组件下载 API](https://yushijinhun.github.io/authlib-injector/en/get-authlib-injector.html)，查阅日期 2026-10-23。

- 用户先读取认证服务器并确认最终 HTTPS API 地址，再输入账号密码登录；支持 ALI 与有界 HTTPS 跳转，拒绝降级 HTTP。携带密码/令牌的请求不自动跟随重定向。
- 多角色登录显示角色选择，经 refresh 绑定所选角色；启动前 validate，失效则 refresh，身份变化时要求重新登录。
- 身份键包含认证服务器、登录标识、角色 UUID，避免同 UUID 跨服务器或跨账号串号。与原有离线/微软账户共用 `accounts.json`。
- `accounts.json` 仅保存账户信息。持久化令牌进入 macOS Keychain，密码不保存；关闭记住登录时仅保留会话。退出可请求服务器撤销令牌并清理本地凭据。
- 游戏启动使用官方 authlib-injector 下载 API 与 SHA-256 校验，加入 agent 和预取元数据 JVM 参数；元数据与签名公钥先做结构/大小检查。
- 外置皮肤、披风按角色声明的权限提供查询、预览、上传、清除。图片限制大小和尺寸，上传前界面重新编码 PNG。没有上传权限时准确报错。

验收边界：协议模拟测试不等于真实外置服务器或多人联机测试。统一通行证专属模式、本地 3D 角色预览仍未实现；微软登录本身沿用已有能力且仍缺真实账户验收。外置认证不是微软正版服务验证的替代通道。

## 微软与离线皮肤

- `MicrosoftSkinService` 仅使用已登录 Minecraft Services 会话，读取账户外观、上传/选择/恢复皮肤、切换/隐藏账户已拥有的披风。API 路径参考已查阅的 [XMCL SDK mojang.ts](https://github.com/voxelum/minecraft-launcher-core-node/blob/master/packages/user/mojang.ts)。令牌仅发送至官方 API 的 Authorization 头，不跟随重定向；账户 UUID 不一致时中止。
- `SkinManagerWindow` 提供以上入口、二维 PNG 预览和本地皮肤导入；微软操作仍需要合法 OAuth client ID 及真实账户，当前只有模拟协议验收，没有真人账户测试。
- 离线皮肤参考 PCL2 `ModLaunch.vb` 的资源包方案，生成本机默认皮肤替换包，保留账户 UUID。它不会上传、同步给其他玩家，也不伪造正版皮肤；模型仍由游戏 UUID 决定，同一客户端中其他使用默认皮肤的角色可能显示同一材质。
- 资源包格式优先读取所安装客户端 `version.json`，支持旧版格式与新的 major/minor 格式；仅无此元数据时对 1.6–1.18 使用已知格式映射。1.8+ 使用 64×64 PNG，早期版本使用 64×32；暂不自动转换宽/细模型。
- 保留其他资源包与 options 设置；切换到微软/外置/试玩账户、或清除离线皮肤时移除启动器自己的包。拒绝覆盖同名用户文件，图片保存在独立缓存并按 SHA-256 校验。
- Desktop 与 CLI 的账户启动路径均准备离线皮肤；独立导出的离线脚本沿用实例当前资源包，不会同步之后更改的皮肤设置。

## 开发接入

```csharp
await InstanceWorkspace.OpenAsync(owner, service, selectedId, RefreshProfiles);
var java = await new LauncherSettingsStore(paths).ResolveJavaAsync(service, version, profile.GameDirectory, progress, ct);
await new AccountToolsWindow(accounts, RefreshAccounts).ShowDialog(owner);
// 外置账户：ResolveAsync 会校验/刷新；准备启动后添加经过下载校验的认证组件。
plan = ExternalAuthentication.AddJvmArguments(plan, await accounts.ExternalLaunchArgumentsAsync(account.Id, service, ct));
await new SkinManagerWindow(accounts).ShowDialog(owner);
new OfflineSkinService(paths).Prepare(account, version, profile.GameDirectory, profile.GameVersion, ct);
```

独立测试入口：`InstanceManagementTests.RunAll`、`ExternalAuthenticationTests.RunAll`、`AccountAppearanceTests.RunAll`。新皮肤与 Java 发现测试等待本轮统一构建结果回填；原 0.7 的功能/兼容记录仍保留，不将历史游戏启动成功视为新账户或新窗口验收。
