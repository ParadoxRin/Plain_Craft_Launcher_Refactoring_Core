# 开发指南

当前发布身份、平台范围与限制以根目录 README 和 release.json 为准。本文说明开发机制；本版默认手动升级，不配置测试或生产更新策略。


首次贡献请先按 [开发快速开始](开发快速开始.md) 跑通最小客户端；按改动选择 [测试指南](测试指南.md) 中的验证。本文保留底层命令、调用说明和独立部署细节。

## 1. 环境、构建与验证

从仓库根目录执行命令，SDK 版本以 `global.json` 为准。macOS ARM64 安装包要求 macOS 14+、Xcode Command Line Tools、Python 3 和 curl；其他平台的核心测试范围见 CI，不据此声称完整游戏已验收。

```sh
python3 scripts/bootstrap-dotnet.py
export DOTNET="$PWD/.tooling/dotnet/dotnet"
export DOTNET_CLI_HOME="$PWD/.cache/dotnet-home"
export AVALONIA_TELEMETRY_OPTOUT=1
"$DOTNET" build PCLCS.Core.slnx -c Release -m:1 -nr:false
"$DOTNET" build src/Pcl.Desktop/Pcl.Desktop.csproj -c Release -m:1 -nr:false -p:UsedAvaloniaProducts=
"$DOTNET" build tests/Pcl.Tests/Pcl.Tests.csproj -c Release -m:1 -nr:false
"$DOTNET" tests/Pcl.Tests/bin/Release/net10.0/Pcl.Tests.dll artifacts/core-tests
python3 scripts/test-component-packages.py
python3 scripts/test-component-legal.py
```

测试目录必须全新；这些 .NET 测试是控制台程序，`dotnet test` 成功不能替代执行 DLL。按变更范围选择 `tests/` 中的账户并发、Host 更新、契约、日志和内容包测试；具体命令以 `.github/workflows/` 为准。CI、fixture、图形界面与真实账号/世界保存分别证明不同范围。

Desktop 的 `TestSupport/` 仅在 `-p:EnableDesktopAcceptance=true` 时编入。测试构建使用独立的 `artifacts/desktop-acceptance/bin` 和 `obj`，不会覆盖默认程序。先构建 Host，再构建测试 Desktop：

```sh
"$DOTNET" build src/Pcl.Host/Pcl.Host.csproj -c Release -m:1 -nr:false
"$DOTNET" build src/Pcl.Desktop/Pcl.Desktop.csproj -c Release -m:1 -nr:false \
  -p:EnableDesktopAcceptance=true -p:UsedAvaloniaProducts=
```

测试程序位于 `artifacts/desktop-acceptance/bin/Release/net10.0/PCL-MacPort.dll`。运行时设置 `PCL_HOST_ASSEMBLY` 为独立 Host DLL 的物理绝对路径、`PCL_DOTNET` 为 SDK 可执行文件。各 UI 探针要求的隔离标记和参数见 `TestSupport/` 对应文件；不能指向个人数据。旧包探针脚本需显式提供测试构建，不可对默认正式程序使用 smoke 参数。

生成安装包与组件包：

```sh
PCL_RELEASE_OUTPUT="$PWD/artifacts/macos-build" bash scripts/build-macos.sh
PCL_COMPONENT_OUTPUT="$PWD/artifacts/component-build" bash scripts/build-components.sh osx-arm64
```

输出目录必须未被使用。版本读取 `release.json`；原生窗口桥从源码构建，LWJGL Agent 使用 vendor 中固定校验和的唯一来源。组件包仅生成 client 和 host ZIP；集成测试临时组装 `assembled/host`，不归档组合目录。面向普通用户的 `.app` 安装布局仍由安装包流程组装，签名后不能修改；当前 ad-hoc 签名不等于 Developer ID 公证。

依赖许可按发布目录中的 `.deps.json` 精确收集，保留实际版本的许可证、NOTICE、NuGet 元数据与依赖清单；缺少指定版本缓存时构建拒绝继续。不得用开发电脑其他缓存版本填补。

## 2. 从源码跑通客户端 → Host

```sh
cd -P "$PWD"
"$DOTNET" build src/Pcl.Host/Pcl.Host.csproj -c Release -m:1 -nr:false
"$DOTNET" build examples/Pcl.MinimalClient/Pcl.MinimalClient.csproj -c Release -m:1 -nr:false
```

交互参数与独立部署步骤见 [最小客户端](../examples/Pcl.MinimalClient/README.md)。开发 Desktop 可连接同次构建的 Host：

```sh
PCL_HOST_ASSEMBLY="$PWD/src/Pcl.Host/bin/Release/net10.0/Pcl.Host.dll" \
PCL_DOTNET="$DOTNET" \
  "$DOTNET" src/Pcl.Desktop/bin/Release/net10.0/PCL-MacPort.dll --data-root "$PWD/artifacts/dev-data"
```

使用物理绝对路径，避免 `/var` 与 `/private/var` 等别名混用导致 `ATTACH_FAILED`。独立自包含组件用 `PCL_HOST_EXECUTABLE` 指向 Host 可执行文件。不同测试使用不同数据根，不要同时启动两个可写 Host 指向同一目录。

## 3. 五类包的入口地图

| 包 | 运行/工具入口 | 主要 API 或调用点 | 开发定位 |
|---|---|---|---|
| 客户端 | Desktop 的 `PCL-MacPort`；CLI 的 `Pcl.Cli.dll`；交互示例 `Pcl.MinimalClient.dll` | `HostClient`、`LauncherSession`、`WorkspaceApi` | `src/Pcl.Client`、`src/Pcl.Desktop/Bootstrap/RemoteComposition.cs`、`examples/Pcl.MinimalClient` |
| Host | `Pcl.Host --update-probe`；实际会话通常由 SDK 启动 | `host.hello`、安装/游戏/账号/页面/资源/订阅 RPC | `src/Pcl.Host/Program.cs`、`PrivatePipeServer.cs`、`Composition/HostRuntime.cs`；DTO 在 `src/Pcl.Contract` |
| 数据 | 无常驻可执行进程；管理入口 `Pcl.ContentPack.dll` | `content.update.status` / `content.update.begin`；内部 `ContentPack.Verify/Install/Load/Rollback/Cleanup` | `src/Pcl.Host/ContentUpdates.cs`、`src/Pcl.Core/Adapters/Content`、`tools/Pcl.ContentPack` |
| 外部运行环境 | Java 的 `bin/java`；EasyTier core/cli 由 Host 管理 | `workspace.java.inspect/discover`、`workspace.link.*`，经页面工作区封装调用 | `JavaService.cs`、`EasyTierService.cs`、`Adapters/Pages/WorkspaceExecutionAdapter.cs` |
| 开发与验证 | `scripts/`、`tests/`、`tools/Pcl.CoreDiagnostics` | 构建/签名/验收脚本，不属于用户业务 RPC | 四个 `PCLCS.*.slnx`；五类包连接规范的验收表 |

内部 Core 函数只是维护定位，不是给普通客户端直接调用的接口。业务能力通过 Host 暴露。消息定义以 `src/Pcl.Contract` 为准，传输实现见 `src/SharedProtocol`。

## 4. .NET 函数调用速查

`HostClient(string dotnetExecutable, string hostAssembly, string dataRoot, bool reconnectable = false)`：第一个参数在自包含模式实际上是 Host 可执行文件；第二个传空字符串。在 FDD 模式第一个是 dotnet，第二个是 Host DLL。需要重连/更新时显式传 `reconnectable: true`。

```csharp
await using var client = new Pcl.Client.HostClient(hostExecutable, "", dataRoot, reconnectable: true);
var hello = await client.HelloAsync(ct);
// 检查 hello.Capabilities 和 hello.InstallationTarget 后再使用具体功能。
await client.ShutdownAsync(ct); // 显式业务退出；DisposeAsync 只释放客户端连接。
```

图形客户端通常创建 `LauncherSession(client)` 并 `await session.InitializeAsync()`；它提供工作区与会话状态管理。`WorkspaceApi(session.Workspaces)` 将工作区操作封装成异步页面任务，不是绕过 Host 的本地执行器。

| 功能 | 调用与返回 | 必要处理 |
|---|---|---|
| 握手 | `await client.HelloAsync(ct)` → `HostHello` | 协议/目标/能力检查；不以产品版本号代替功能能力 |
| 受理安装 | `await client.Installations.AcceptAsync(new InstallCommand(key, request), ct)` → `OperationAcceptance` | 持久保存 key 与 OperationId；受理不是安装完成 |
| 查询/等待安装 | `GetAsync(id, ct)` / `WaitAsync(id, ct)` → `OperationSnapshot` | Get 可为 null；终态检查 `State`、`ErrorCode`、`Result` |
| 安装事件 | `((IVersionInstallEvents)client.Installations).WatchAsync(id, ct)` | 用 await foreach；断线恢复遵守快照/序号规则 |
| 取消安装 | `await client.Installations.CancelAsync(id, ct)` | 请求取消后继续确认终态；取消等待 token 不等于取消后台任务 |
| 启动游戏 | `client.Launches.AcceptAsync(GameLaunchCommand, ct)` → `OperationAcceptance` | 先请求 game.guidance，真实展示并获取用户确认；不传令牌/Java 参数 |
| 等待启动/游戏 | `Launches.WaitAsync(id, ct)` / `GetGameAsync(gameProcessId, ct)` | 启动操作成功与游戏运行/退出是不同状态 |
| 停止游戏 | `await client.Launches.StopGameAsync(gameProcessId, ct)` | 仅操作 Host 公开的受控 ID |
| 页面/工作区 | `new WorkspaceApi(session.Workspaces).CallAsync<T>(method, instanceId, args, ct)` | T 必须对应返回 DTO；method 为受支持的 workspace 操作 |
| 账号快照 | `client.Call<AccountSnapshot>("account.snapshot", new { }, ct)` | 返回公开状态；不得期待获得微软原始令牌 |
| 断开再连接 | `DisconnectAsync()` → `ReconnectAsync(ct)` | 保持同一业务 operationId/幂等键，重新确认 hello/状态 |
| Host 更新 | 连接前 `ConfigureUpdates(policy, privateStore)`；`CheckForUpdatesAsync`；`ApplyUpdateWhenIdleAsync` | 必须使用可信策略；忙时不强制切换；状态可能仍为 staged |

安装请求示例已在 `examples/Pcl.DeveloperQuickstart/Recipes.cs` 编译验证：

```csharp
var hello = await client.HelloAsync(ct);
var request = new VersionInstallRequest("1.21.1", "vanilla", hello.InstallationTarget!);
var accepted = await client.Installations.AcceptAsync(new InstallCommand(savedKey, request), ct);
var result = await client.Installations.WaitAsync(accepted.OperationId, ct);
if (result.State != "succeeded") { /* 展示 result.ErrorCode，保留 operationId */ }
```

调用前必须检查目标不为空与 `version.install.v3`；完整防护见 `Recipes.InstallAsync`。示例里的版本只是调用演示，不保证网络、账户或目标平台都满足安装条件。

Java 工作区调用（已实际验证）：

```csharp
var api = new WorkspaceApi(session.Workspaces);
var java = await api.CallAsync<Pcl.Core.Contracts.Workspaces.JavaRuntime>(
    "workspace.java.inspect", null, new { path = javaExecutable }, ct);
// java.MajorVersion / Architecture / Executable
```

账号登录、授权引导、资源搜索、实例管理的字段较多，必须查对应 `src/Pcl.Contract/Accounts|Launch|Workspaces|Pages` 定义及 `examples/Pcl.MinimalClient/MinimalLauncher.cs`。不要根据名称猜参数。普通页面调用经 `HostPageOperations` → `page.begin/get/cancel`；workspace 名称不能直接作为顶层 RPC 发出。

## 5. 非 .NET 接入及错误约定

传输为 UTF-8 单行 JSON（NDJSON），不是 JSON-RPC 2.0。私有管道先 attach 后 hello；stdio 直接入口 `Pcl.Host --data-root /absolute/root` 先 hello。`--pipe` 模式包含端点、进程出生证明与重连约定，参照 SDK/SharedProtocol 实现，不把 stdio 示例当成完整可重连协议。

```json
{"protocolVersion":1,"id":"0123456789abcdef0123456789abcdef:1","method":"host.hello","params":{"minimumVersion":1,"maximumVersion":1}}
```

各连接请求 ID 前缀独立，序号从 1 连续递增。遵守 hello 帧限制。响应与事件区分关联；`event.changed` 不是请求响应。大资源使用 `blob.open/read/page/close` 的有界句柄接口。字段名、大小写与 DTO/序列化规则见 Contract 和 `Program.cs`。

捕获 `OperationRejectedException` 并读取 `Code`；已受理的失败从任务快照读取 `ErrorCode`。超时/断线先查询原任务，不能生成新 key 重复执行。`HOST_UPDATE_IN_PROGRESS` 等暂态应等待重连；协议/能力缺失应拒绝对应功能，不能改为直接读写核心文件。错误码集合以具体接口实现为准，本文不虚构统一重试字段。

## 6. 数据、工具与更新器入口

内容工具在仓库根目录构建：

```sh
dotnet build tools/Pcl.ContentPack/Pcl.ContentPack.csproj -c Release
# 只验证：
dotnet tools/Pcl.ContentPack/bin/Release/net10.0/Pcl.ContentPack.dll \
  verify /absolute/content.json /absolute/trusted-policy.json 0.43.0
# 管理员离线部署；下一次 Host 启动生效：
dotnet tools/Pcl.ContentPack/bin/Release/net10.0/Pcl.ContentPack.dll \
  install /absolute/content-store /absolute/trusted-policy.json 0.43.0 /absolute/content.json
```

`status` / `rollback` 参数为 `<store> <policy> <hostVersion>`；`install` 另加最后一个内容文件参数。客户端普通更新使用 `content.update.begin`，不能提交任意公钥/URL。签名生产流程见 `build-unified-release.sh` 和 `tools/Pcl.UpdatePack`；源码和交付包均不得包含私钥。

Mac 客户端自身更新入口在 `src/Pcl.Desktop.Updates/ClientSelfUpdate.cs`，UI 接线在 `src/Pcl.Desktop/ClientUpdateUi.cs`，退出及安装接线在 Desktop Program/App；独立助手在 `tools/Pcl.ClientUpdater`。这是依赖进程退出、事务和启动确认的完整协议，不应单独调用文件替换函数。复用现有接线，使用 `test-client-self-update.sh` 验证，不将内部安装请求当作公开 RPC。

Java/EasyTier 按现有 Host 适配器从来源获取并校验，具体版本和来源由运行环境清单及对应适配器管理。已有工具可用 `test-package-connectivity.sh` 复验。不要把开发电脑的绝对路径、运行回执或用户缓存复制到他人配置。

## 7. 独立协作与变更流程

- 核心：`PCLCS.Core.slnx`；客户端：`PCLCS.Clients.slnx`；SDK：`PCLCS.ClientSdk.slnx`；开发工具：`PCLCS.Tools.slnx`。以根目录实际解决方案名称为准。
- 导出独立客户端需先运行 `scripts/build-client-sdk.sh`，再用 `export-client-workspace.py` 提供 SDK feed；导出核心用 `export-core-workspace.py`。导出的客户端不携带 Core/Host/vendor 源码；macOS 窗口桥在导出目录由源码构建。
- UI/窗口修改放 Desktop/Native；规则放 Domain；来源适配放 Core，接口按需放 Ports；长任务在 Application/Core 编排，经 Contract、Host、Client 暴露。
- 先定义用例与验收边界，再复用搜索、安装事务和任务机制。跨包协议变更由主分支协调，不能让包自行修改共享 Contract。
- 运行受影响的规则、协议、取消、失败和文件写入测试。源码存在不代表真人账户或世界保存已通过；平台行为在对应平台验证。
- 发布流程见 [发布与维护](发布与维护.md)、[分包构建与签名](分包构建与签名.md)。测试构建不得发布；构建脚本强制关闭 Desktop 验收编译开关。
- 提交前核对隐私、来源许可、当前文档和版本边界。`audit-release-privacy.py` 与 `audit-repository-privacy.py` 保留为常用检查；过往一次性矩阵修订和阶段验收报告不再保存在当前源码树。
