# 完整扩展示例：让客户端知道搜索来源为何不可用

这是对已经落地的 CurseForge 来源状态功能的逐层讲解，附可直接执行的验证入口。无需添加教学专用生产 RPC，也不需要真实密钥。场景：搜索来源缺少密钥、被拒绝或限流时，界面解释原因，其他来源仍可显示。

## 先定义行为

- 未配置凭据时明确显示 CURSEFORGE_KEY_REQUIRED，不伪装成“没有搜索结果”。
- 401/403、429、网络错误分别映射为安全错误码，原始响应和密钥不进入结果。
- 来源失败在来源级聚合，不能让其他来源一起失败。
- 新客户端读取结构化可用性；旧客户端仍能读取 SourceStatus 和 HasErrors。
- 整体任务取消继续向外传播，不能把取消吞成来源不可用。

## 1. 定义可传输的结果

打开 [SearchViews.cs](../src/Pcl.Contract/Workspaces/SearchViews.cs)。SearchPage 增加默认空数组的 Availability，元素为 SearchSourceAvailability（Source、Available、Code、Message、Retryable）。旧字段继续保留，结果不含原始异常或凭据。

新增字段时同时确定缺失值的含义。本例空 Availability 表示没有结构化状态，客户端回退旧文本，不能解释成“所有来源可用”。该能力没有专用 hello 标识，应使用字段回退，不发明能力字符串。

## 2. 在来源边界转换失败

打开 [CurseForgeAccess.cs](../src/Pcl.Core/CurseForgeAccess.cs) 和 [CurseForgeCatalog.cs](../src/Pcl.Core/CurseForgeCatalog.cs)。前者提供安全错误码、提示和 Retryable 分类，后者处理请求、授权和响应。

增加一种错误时：决定它是否允许重试，映射到固定安全提示，验证响应正文和密钥不会进入日志/DTO。路径、HTTP 和秘密读取属于适配层，不进入 Domain。已有端口足够时不增加无用途的 Ports 接口。

## 3. 聚合来源，再投影成 Contract

[UnifiedResourceSearch.cs](../src/Pcl.Core/Adapters/Search/UnifiedResourceSearch.cs) 将单来源失败保留为来源状态；[UnifiedSearchSession.cs](../src/Pcl.Core/Adapters/Search/UnifiedSearchSession.cs) 管理分页。

[WorkspaceSearch.cs](../src/Pcl.Core/Adapters/Pages/WorkspaceSearch.cs) 的 `workspace.search.page` 分支读取实例、查询会话，构造 SearchPage，把内部错误码转换为 Availability。选择句柄由 Host 生成，UI 不获得任意下载执行权限。

修改纯身份/兼容规则时才进入 Domain/Search；这个状态字段不要求修改 Domain。完整功能不代表每层都必须新增文件。

## 4. 接入已有任务与 Host 链路

调用顺序：

```text
WorkspaceApi.CallAsync<SearchPage>
  → HostPageOperations（page.begin / 查询 / 取消）
  → Host Program 分发
  → PageOperationService
  → PageExecutionAdapter / WorkspaceSearch
  → UnifiedSearchSession / 来源适配器
```

对应入口：[WorkspaceApi](../src/Pcl.Client/WorkspaceApi.cs)、[HostPageOperations](../src/Pcl.Client/HostPageOperations.cs)、[Host 分发](../src/Pcl.Host/Program.cs)、[PageOperationService](../src/Pcl.Application/Pages/PageOperationService.cs)、[组合根](../src/Pcl.Host/Composition/HostRuntime.cs)。

本例复用已有任务，不增加顶层 RPC。真正新增 workspace 方法时，需要检查 [WorkspaceOperations](../src/Pcl.Contract/Pages/WorkspaceOperations.cs) 的允许项/只读分类、[PageResourcePolicy](../src/Pcl.Application/Pages/PageResourcePolicy.cs) 的资源声明、执行分发和恢复行为。不要把写操作登记为只读来绕过冲突控制。

## 5. 客户端呈现与回退

[UnifiedSearchWindow.cs](../src/Pcl.Desktop/UnifiedSearchWindow.cs) 的搜索调用通过 WorkspaceApi 取得 SearchPage；使用结构化状态提示不可用来源，并保留 SourceStatus 展示。UI 不根据 HTTP 状态自己推断授权，也不接触来源密钥文件。

调用形状已经在下面的真实 Host 探针中编译执行：

```csharp
var page = await api.CallAsync<SearchPage>("workspace.search.page", instanceId,
    new { query = "test", provider = "curseforge", online = true,
          gameVersion = "", loader = "", kind = 0 }, ct);
// page.Availability 缺失/为空时回退 page.SourceStatus；实例由 Host 管理。
```

这里 instanceId 必须是有效实例。教学探针构造隔离 fixture；产品客户端应通过 Host 创建/选择实例，不能复制测试代码直接写 profile.json。

## 6. 一条命令复验

```sh
python3 dev.py test sources
```

入口构建真实 Host 和 [Pcl.CurseForge.Tests](../tests/Pcl.CurseForge.Tests/Program.cs)，为本次运行创建新目录，依次执行：

1. 来源夹具：缺失/非法密钥、401/403/429、超时/网络异常、错误响应、取消、镜像凭据隔离、其他来源继续返回、DTO 的旧字段兼容。
2. 真实 Host 探针：缺少密钥与合成非法密钥的安全结果；本地百科查询不受另一个来源失败影响。

测试失败返回非零。数据在 artifacts/dev/sources-*，不访问个人实例；不需要真实 CurseForge 密钥，不代表真实线上授权通过。界面视觉/交互仍需运行 Desktop 验证，本命令只覆盖夹具和真实协议。

## 把这个例子用于下一个功能

提交前写清：用户看到什么 → 哪层负责判断 → 增加哪些 Contract 字段 → 旧客户端如何降级 → 权威执行在哪 → 哪些成功、拒绝、取消行为已验证。修改范围优先沿现有链路扩展，不为一个显示字段新建第二套任务系统。
