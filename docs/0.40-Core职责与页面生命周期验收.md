# 0.40 · Core 职责与页面生命周期

日期：2026-10-27。对象：macOS arm64 的现有 Avalonia 客户端与独立 Host。

## 实现与所有权

| 职责 | 本次实际实现 | 为什么这样划分 |
|---|---|---|
| 账户用例 | `Pcl.Application/Accounts/HostAccountService` 管理受理、幂等、挑战、取消与终态；通过 `IAccountBackend` 调用原认证实现 | 应用状态机不再构造 HTTP/钥匙串实现，临时挑战不落 receipt |
| 游戏用例 | Application 的 `ExistingGameLaunchExecutor` 与 `LaunchGuidanceService` 应用启动规则；Core 的 `GameLaunchBackend` 保留原准备、启动及进程观察 | CLI 和 Host 使用同一用例；不改正版验证、离线策略或独立运行语义 |
| 纯规则 | `TargetPlatform`、Java 内存/GC 规则、旧参数解析、PNG 校验与皮肤布局转换归属 Domain | 规则使用显式输入；宿主探测由 `HostPlatform.Detect` 执行。没有 Domain → Ports 引用 |
| 运行时组合根 | `Pcl.Host/Composition/HostRuntime` 统一组装服务、等待已受理工作、逆序释放资源；Program 只持有根作用域及协议生命周期 | 服务借用共享资源；只有根拥有释放权。重复关闭/释放复用同一 Task |
| 页面导航 | `WindowNavigation` 按页面类型和实例/查询上下文复用非模态管理页 | 重复打开保留当前输入，不再制造多个相同页面；不同实例页面互不覆盖 |
| 真正的对话框 | `WindowPresentation.PresentAsync<T>` 保留确认、选择、预览的模态返回值 | 不把所有窗口一律改成页面，也不丢失 `Close(result)` 的结果 |
| 视图生命周期 | `ViewLifetime` 登记活动工作和清理；`WorkspaceWindow` 统一关闭协调；MainWindow 等待全部子窗口 | 普通关页等待受理工作，不隐式取消 Host；应用退出才请求取消。先收尾再清理，父窗口等待子窗口 |

现有账户、实例、皮肤文件格式、RPC 方法和 receipt 格式不变。`TargetPlatform.Current` 的内部便捷入口替换为显式宿主 Adapter；仓库内消费者已更新，不承诺历史外部二进制 SDK 兼容。

### 页面范围

账户、皮肤、实例管理、本地资源、整合包、加载器、官方文件、CurseForge、多源搜索、缓存网络、设置帮助、离线脚本、OptiFabric、联机、页面任务和任务中心统一接入。窗口自己的 CTS/定时器/位图在工作结束后清理；窗口不释放 Host 或共享账户服务。

导航仍然使用拥有者窗口，不是新的标签页框架。状态保留指**仍打开页面的复用**，不声称关闭后草稿或全部页面历史已经持久化。关闭中的页面拒绝新任务。原系统关闭/应用退出的有界等待由 RemoteLifetime 协调；超时不当作已经安全释放。

## 架构守卫与后续边界

- `Core/Application` 禁止重新放入应用用例；`Pcl.Application` 编译依赖仍只允许 Contract/Domain/Ports。
- Domain IL 禁止本地文件、网络、进程、宿主探测、原生调用和隐式时间/随机输入；允许内存流、压缩和纯字节处理。这是架构约束，不是安全沙箱。
- 生产 Shell 的模态显示只经 `WindowPresentation`；测试探针有明确隔离。
- DEBT-003 在**现有 Avalonia 页面导航/窗口生命周期**范围内关闭。后续原生客户端仍需实现等价的生命周期契约。
- Core 仍包含复用的安装、整合包、资源事务及 `PageExecutionAdapter` 执行实现；这些不是已变成纯 Domain。复杂安装器/资源事务拆分应按下一条实际用例推进，不能仅靠移动文件或增加空接口声称完成。
- 本次不改功能矩阵子进度，不靠重命名状态关闭功能缺口；百宝箱取消沿用上一轮用户决定。

## 复现

使用仓库 `.tooling/dotnet/dotnet`。构建加 `-m:1 -nr:false -p:UseSharedCompilation=false -p:UsedAvaloniaProducts=`；首次 restore 可从 `.cache/nuget` 离线恢复。

1. 构建 `src/Pcl.Desktop/Pcl.Desktop.csproj`、`tests/Pcl.Architecture040.Tests`、`tests/Pcl.PhaseTwo.Tests`、`tests/Pcl.ShellBoundary.Tests`。
2. 直接执行测试 DLL。Architecture040 参数为 JSON 报告路径；PhaseTwo 参数为全新隔离目录和 `--without-keychain`；ShellBoundary 参数为全新隔离目录、JSON 报告路径和 `--fixture`。
3. `PCL_ARCH_TEST_OUTPUT=artifacts/architecture-0.40/guard python3 scripts/test-architecture-guard.py`。
4. 桌面程序使用 `--data-root <全新隔离目录> --navigation040-smoke --navigation040-report <JSON路径>`。需要 macOS 图形会话，探针自动打开并关闭测试窗口。
5. `bash scripts/build-release.sh` 生成 0.40 本地自包含包，空 OAuth 配置、源码路径映射、隐私检查及 ad-hoc 签名。此包未进行 Developer ID 公证，也不自动上传仓库。

发布包验证另见同目录 `artifacts/architecture-0.40/package-navigation.json` 和发布审计侧车；只有相应文件实际通过才代表发布包复测完成。
