# 微软登录开发配置

2026-10-26：仓库已移除原作者的应用client ID和租户ID。默认构建不发起微软登录，免登录下载和离线功能保持可用。

微软账号用于确认用户身份；client ID用于标识发起授权的应用，两者不能互相替代。微软设备码协议要求client_id字段，见[微软官方文档](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)。开发者需要自己有权使用、并获准访问Minecraft相关API的应用标识，然后使用自己的微软账号进行验证；需要验证正版权益和启动时，账号应拥有Java版。不要填写原作者标识或借用其他启动器的ID。

## 本地构建配置

在源码根目录创建被Git忽略的 `.local/microsoft-application.json`：

```json
{
  "clientId": "填写你自己的应用GUID"
}
```

仅允许clientId字段；不要添加密码、clientSecret、令牌或账号资料。按正常构建流程重新编译Core/Host即可。也可通过MSBuild属性 `-p:MicrosoftApplicationConfig=/absolute/path/to/microsoft-application.json` 指定自己的文件；此选项优先于 `.local` 文件。不配置时使用源码中的空值。

配置会嵌入构建产物，分发该产物也会分发你自己的公开应用标识。不要将本地配置提交；公开应用标识不是密码，但是否分发仍由应用所有者决定。为恢复未配置构建，移开 `.local` 配置并清理相应bin/obj后重新编译，避免沿用旧产物。

测试使用新建隔离数据目录，不复用原作者账户或钥匙串。已有账户刷新按其记录的原应用ID执行；本次清理不读取、删除或修改本机账户/钥匙串，也不会撤销Entra应用。更换应用后应在隔离目录重新登录，不能把旧refresh token转交给新应用。

## 验证边界

仓库保留协议夹具和历史运行结果。默认未配置测试和使用虚构GUID的HTTP替身测试不等于真实微软或Minecraft服务验收。接手者配置自己的应用后，需自行验证设备授权、权益、刷新、钥匙串和游戏启动；密码及确认操作只在微软网页或系统窗口完成。
