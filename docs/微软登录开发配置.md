# 微软登录开发配置

2026-10-27：按应用所有者授权，0.40.1恢复此前获批的 PCL_Mac 公开 client ID，普通用户直接登录自己的微软账号。0.36.1至0.40的空配置属于历史发布策略；没有恢复租户ID、密码、client secret或用户令牌。

微软账号用于确认用户身份；client ID用于标识发起授权的应用，两者不能互相替代。微软设备码协议要求client_id字段，见[微软官方文档](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)。本项目正式包使用所有者授权的应用标识；独立发行者可以改用自己有权使用并获准访问Minecraft API的应用。验证正版权益时应使用拥有Java版的微软账号，不借用其他启动器的应用ID。

## 本地构建配置

在源码根目录创建被Git忽略的 `.local/microsoft-application.json`：

```json
{
  "clientId": "填写你自己的应用GUID"
}
```

仅允许clientId字段；不要添加密码、clientSecret、令牌或账号资料。按正常构建流程重新编译Core/Host即可。也可通过MSBuild属性 `-p:MicrosoftApplicationConfig=/absolute/path/to/microsoft-application.json` 指定自己的文件；此选项优先于 `.local` 文件。没有覆盖文件时使用源码中所有者授权的公开ID。正式发布脚本明确选择源码配置，避免意外打入本地覆盖配置。

配置会嵌入构建产物，分发该产物也会分发公开应用标识。不要将本地覆盖配置提交；公开应用标识不是密码，但是否分发仍由应用所有者决定。需要空配置构建时，使用仅含 `{"clientId":""}` 的本地文件，通过MicrosoftApplicationConfig显式指定并重新编译。

测试使用新建隔离数据目录，不复用原作者账户或钥匙串。已有账户刷新按其记录的原应用ID执行；本次清理不读取、删除或修改本机账户/钥匙串，也不会撤销Entra应用。更换应用后应在隔离目录重新登录，不能把旧refresh token转交给新应用。

## 验证边界

仓库保留协议夹具和历史运行结果。空配置测试、HTTP替身测试不等于真实服务验收；真实设备码申请成功也不能替代用户登录、权益、刷新或游戏启动验收。密码及确认操作只在微软网页或系统窗口完成。
