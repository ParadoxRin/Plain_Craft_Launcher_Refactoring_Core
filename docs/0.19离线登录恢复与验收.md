# PCL Mac 0.19：恢复 PCL2 离线登录

日期：2026-10-24。按用户最新要求恢复离线身份启动，替代 0.12–0.18 的仅微软验证启动限制。

## 实现

- 对照 PCL 2.99.0.0 `ModLaunch.McLoginLegacyStart` 与 `McLoginLegacyUuid`：玩家名称、MeloongCore 稳定哈希构造的 UUID、UUID 占位令牌、legacy 用户类型及名称历史。
- 首页显示“离线登录”；首次使用默认提供离线模式，有历史账户时恢复上次选择的类型。输入有效名称可直接启动并保存名称，也可先使用“使用此名称”按钮。
- 保存多个离线名称、切换及移除账户；固定 UUID 维持同名身份。原有本地皮肤资源包路径继续使用，不宣称向其他玩家发布在线皮肤。
- 离线启动只验证本地身份字段一致性，不创建或伪造微软购买证明。微软模式仍要求有效权益与档案证明；注销、过期或伪造 msa 会话不会自动降级为离线。
- CLI 支持 `launch --offline-name <玩家名>`，也可使用已保存的离线账户 ID。
- 离线账户不读取钥匙串、不调用微软认证接口。游戏或首次依赖下载自身的网络请求与离线身份解析分开。

## 验证

213 项回归通过，包括离线身份合法性、名称/UUID/令牌字段篡改拒绝、微软验证证明不可伪造，以及账户进程重开后的离线解析不访问认证网络或钥匙串。

实际打包应用通过账户控件创建、切换离线身份，再通过“启动游戏”按钮以 PCL_Offline 启动 1.21.1，进入独立存档副本。第一次正常保存退出后，整个应用重开，自动恢复同一离线账户，再次进入同一世界并正常退出。用户确认标记和位置保留。测试目录没有微软账户，账户索引只含离线类型，没有 client ID 或记住登录凭据。

两次均有单人服务器启动/停止及存档更新。第一次日志无 ERROR；第二次退出出现一条 OpenAL `Stop: Invalid name parameter`，保留为已知音频退出错误，未影响本次保存与重进，不标为全日志无错误。

证据：`artifacts/verification-0.19/regression/test-results.json`、`offline-world-roundtrip.json`、`first-world-reviewed.json` 与 `offline-data/evidence/offline-desktop-reentry.json`。

## 边界

本版提供本地离线身份，不代表微软正版验证。要求在线身份认证的服务器仍需相应正版账户。微软 AppID allow list 审核只记录微软登录 API 的应用授权，不能作为离线身份的购买证明。

PCL2 自定义皮肤的全部策略、所有外置登录方式和完整功能矩阵尚未全部复刻。旧版包与原始存档保留。Apple Silicon 自包含开发版，ad-hoc 签名，尚未公证。
