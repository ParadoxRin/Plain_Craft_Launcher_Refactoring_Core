## 实现

- `Pcl.Client/Updates`：可信策略、签名feed、HTTPS重定向验证、版本/平台/协议/数据epoch/能力匹配、隔离暂存、全部文件校验、更新指针及失败回退；只依赖Contract。
- Host：无数据探针、hello构建身份、原子空闲退出。登录、皮肤、安装、页面任务、已知游戏或联机活跃时拒绝更新，既有业务不被主动取消。
- 参考客户端：显式部署策略文件后，LauncherSession拥有自动检查与空闲更新循环；退出取消/等待该循环。无策略文件时保持原行为。
- 最小客户端：提供更新策略/存储参数和check/apply/status命令，证明无需Core即可接入。
- 发布工具：先完成平台签名及隐私检查，再用发布者私钥生成签名整包与feed；不内置或上传私钥。
- 故障处理：下载/归档/哈希/探针失败保留旧版；实际新Host启动失败恢复旧指针并重连；trial未确认而客户端崩溃，下次回退，并通过会话请求遗留候选空闲退出，不按PID强杀。

## 不外推的范围

1. 测试feed由受控HttpMessageHandler提供，验证签名、归档与实际执行；不是正式CDN端到端运营测试。默认官方签名频道尚未配置，发布者需提供自己的信任根和源。
2. CI用framework-dependent包；生产自包含包的打包命令已经给出，但本次不声称完成新版本三平台安装包、Apple公证或Windows代码签名验收。
3. 原生凭据使用合成值，没有读取本机个人钥匙串或进行真人微软授权/皮肤上传。账户索引保持与既有核心测试通过，不等于新一轮真人认证验收。
4. 游戏只验证渲染与进程存活，不覆盖世界保存重进、所有加载器或Intel/Rosetta。
5. 自动更新不执行数据格式迁移，不替换UI，不进行运行时代码热替换。自动回退是启动/握手保障，不是任意长期业务故障回退。目录元数据硬断电持久性未模拟。
6. 安装包签名、更新清单签名和用户账号凭据是三个独立边界；微软OAuth client ID和Keychain作用域未改变。

本轮不修改功能矩阵标签；UI-008的完整客户端自身升级及默认发布运营仍保留缺口。原始报告位于忽略目录`artifacts/host-updates/`，公开结果仅包含范围、断言名、计数与哈希。
