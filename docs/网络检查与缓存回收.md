# 网络检查与缓存回收

`CacheNetworkWindow` 通过 `NetworkDiagnosticsService` 与 `TemporaryDownloadCache` 提供独立入口，使用当前数据目录及网络代理配置。

网络检查由用户点击触发，向选定 HTTPS 地址发送 0–65535 的 Range 请求。无论服务端是否支持 Range，最多读取 64 KiB，单次请求 10 秒超时；不跟随跳转、不携带账号令牌、不加入安装队列或修改已有下载。官方版本/Java 清单始终可选；已下载文件中识别到官方资源/库/客户端主机时提供同源样本，配置了镜像则同时提供对应镜像地址。没有对应路径时镜像根地址只用于测试可达性，404 不能用来断言完整文件下载失败。

界面显示 HTTP 状态、响应时间、采样大小和平均采样吞吐。小样本受连接建立、缓存和服务器响应影响，不代表持续带宽或完整下载能力。用户可填写无账号、查询令牌或片段的 HTTPS 文件地址。CLI `network-probe --data-root <目录> [--url <HTTPS文件地址>]` 调用同一核心，回执写入 `evidence/network-probe.json`。

临时缓存预览仅扫描数据目录 `cache/` 与各实例 `.pcl-downloads/` 中超过 24 小时的 `.part`、`.partial`、`.partial-*` 文件，列出相对路径、大小及修改时间。不会扫描已安装 Java、共享 libraries/assets、游戏存档或普通已校验缓存。正在排队/下载的目标、符号链接和较新文件被排除。

用户多选后移动到 `cache-trash/<批次>/`，不会永久删除。移动前逐文件重新检查大小、修改时间、活动任务，使用独占文件访问，预览后变化或被占用的文件跳过；先写恢复记录再移动，以保留异常退出后的恢复依据。恢复只回到允许的临时缓存位置，原位置已有新文件或活动下载时保留回收副本，拒绝路径越界/符号链接。批次可在“缓存回收目录”页恢复。

这不是共享缓存的引用计数垃圾回收；没有自动清理已完成下载、Java 或库，也不宣称实现了 PCL2 的所有缓存策略。新增 fixtures 位于 `AccountNetworkDiagnosticsTests`，实际请求、GUI 和最终构建证据由本轮整合记录提供。
