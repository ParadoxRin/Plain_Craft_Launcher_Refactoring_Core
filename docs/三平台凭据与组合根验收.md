# 三平台凭据与组合根：实现及验收

这是 `main` 在最小客户端之后的增量，不修改固定 `v0.41.0` 安装包，也不修改产品矩阵状态。目标是补齐系统凭据边界和 Host 的实际平台选择；不是宣布 Windows/Linux 全部启动器功能已经可用。

## 实现与责任

`HostRuntime → PlatformAccountSecrets.Create(paths.Root) → IAccountSecrets`。工厂按**运行 Host 的操作系统**选择，不能用 Minecraft 的 TargetPlatform 决定应访问哪个凭据库。已有短命令和游戏进程执行器仍由 Host 创建、持有、排空及释放；本次未更换游戏进程策略。

| 宿主 | 当前适配器 | 持久化和限制 |
|---|---|---|
| macOS | 原 `KeychainAccountSecrets` | 原 service `local.pcl.macport.oauth.*`、路径哈希、账户 ID 和 Security.framework 调用不变 |
| Windows | `WindowsCredentialAccountSecrets` | 当前用户的 Generic Credential，`CRED_PERSIST_LOCAL_MACHINE`；是该用户在本机的持久化，不是所有用户共享。UTF-8 单条上限2,560字节，超限先拒绝，旧值保留 |
| Linux | `LinuxSecretServiceAccountSecrets` | libsecret + 当前用户 D-Bus Secret Service 默认 collection；须有 libsecret 和可用服务。每条最多65,536字节，调用有30秒 GCancellable 预算 |

普通 CLI 账户/启动入口与页面备用账户管理也使用同一工厂，消除遗漏的固定 Mac 绑定。`MacAccountSecrets` 兼容类型和 `keychain-self-test` 保留原 Mac 专用含义。新的最小客户端与 Desktop 不增加 Core 引用。

Windows/Linux 的原生索引只保存应用命名空间和数据根/账户 ID 的哈希。秘密经原生内存参数传递，不放在 shell、argv、普通配置或 RPC 中；临时字节缓冲尽可能清零。托管字符串及系统服务自己的内存不承诺可立即擦除。数据根移动或路径身份改变不会自动搬迁凭据；不能把 Windows 凭据文件复制当成跨账户导出方案。

Linux Get 只有成功搜索且无匹配项时返回 null。缺库、缺会话服务、超时、拒绝解锁都报错，不回退为明文存储。Delete 不使用会静默跳过锁定条目的 clear API：先搜索并确认全部匹配项已解锁，再逐项确认删除。错误不回显原生 GError message。系统服务是当前用户信任边界，不防御该用户下的恶意服务或恶意进程。

登录、刷新、权益检查、皮肤接口和 `IAccountSecrets.Get/Set/Delete` 没有更改。现有 `AccountBackend` 在持久化抛出 CryptographicException 后保留仅本次会话登录；不宣称“记住登录”成功，也不创建明文备用库。已保存账户遇到库不可用时恢复/删除会报错，不能误报已清除。

## 测试方法

`tests/Pcl.PlatformCredentials.Tests` 是原生 Adapter/Host 验收程序，可以引用 Core 来生成隔离测试数据；它不是给客户端的接入范例。只有 `examples/Pcl.MinimalClient` / 对应契约测试遵守 Client+Contract-only 边界。没有给生产 Host 增加写入/读取原始秘密的测试 RPC。

```sh
dotnet build src/Pcl.Host/Pcl.Host.csproj -c Release
dotnet build tests/Pcl.PlatformCredentials.Tests/Pcl.PlatformCredentials.Tests.csproj -c Release
dotnet tests/Pcl.PlatformCredentials.Tests/bin/Release/net10.0/Pcl.PlatformCredentials.Tests.dll \
  /absolute/new-physical-root /absolute/report.json /absolute/host/Pcl.Host.dll
```

只允许全新物理数据目录，所有凭据/账户为本轮随机生成的合成值。子进程恢复使用 stdin 比对，不打印值，不访问微软服务，不进行完整游戏权益认证。测试覆盖原生 CRUD、跨进程恢复、根与账户隔离、UTF-8 字节限制、超限保留旧值、Host 重启及退出登录/删除账户、公开索引/RPC 不含令牌及清理。

CI 的 Windows 使用临时 runner 用户的 Credential Manager；Mac 创建临时测试 keychain 并在结束时删除，验证原 Mac service 可与历史兼容类型互读；Linux 使用 `dbus-run-session`、临时 XDG 目录和独立 daemon 控制目录。Linux 测试要求 `PCL_TEST_PRIVATE_SECRET_SERVICE=1`，会锁定此**隔离**服务的 login collection，验证拒绝后重新解锁仍能读回原值；不得把此环境变量用于真实桌面会话。完整初始化步骤以 `.github/workflows/core-ci.yml` 为准，测试密码仅为公开 fixture，不是用户凭据。

Linux 在同一隔离测试中再开子进程，将 D-Bus 地址指向不存在的 socket，要求 Get/Set/Delete 全部明确拒绝；不能以 null、静默成功或明文文件替代。缺库错误已接线，但 CI 安装了真实库，本轮不把“库缺失”误记成实际复现。

本机 Mac 另外使用更新后的 Host 在全新根执行最小客户端 `live`：真实安装→下载后取消→重连→Host 崩溃→校验续做→托管/独立试玩启动。该项验收图形/材质初始化和 Host 退出后独立游戏继续运行，不计作世界保存或真人登录/皮肤验收。

### 保留的失败与修复

1. [首轮 40654934246](https://github.com/ParadoxRin/Plain_Craft_Launcher_Refactoring_Core/actions/runs/40654934246)：Mac18项、Windows20项凭据检查通过。Linux CRUD/字节限制/缺服务/锁定拒绝已通过，测试夹具错误地把 `gnome-keyring-daemon --unlock` 当成对现有 daemon 再次解锁，导致恢复与清理失败。改为仅替换本轮私有 daemon，使用相同临时加密 keyring。
2. [第二轮 40655393753](https://github.com/ParadoxRin/Plain_Craft_Launcher_Refactoring_Core/actions/runs/40655393753)：暴露真实实现缺陷——替换后 libsecret 默认代理仍绑定旧服务。改为每次 Get/Set/Delete 打开并释放独立 `SecretService` proxy；SecretValue/搜索也使用同一个本次代理。没有自动重试写入，避免重复副作用。新增恢复后跨进程读取与同适配器更新检查。
3. 最终三平台完整重跑通过，所有本轮合成凭据经 Delete 后 Get 确认不存在。第一、二轮失败没有删除、跳过或改断言。原始个人路径/数据库/秘密没有随报告上传。

## 仍未完成及接手顺序

- Windows/Linux 真人微软设备登录、令牌刷新、皮肤与外置认证联调；本轮原生系统调用成功不等于真实账号流程成功。
- Linux 其他 Secret Service 实现（如不同版本 KWallet）、沙箱/Flatpak 权限、用户取消真实桌面提示、跨登录会话恢复；CI 使用真实 GNOME Keyring 的隔离用户会话。
- Windows Credential Manager 对超长凭据的上限是明确限制；未来若要支持更大值，需单独设计原子/加密方案，不截断或落明文。
- Windows 独立游戏文件重定向仍在 `SystemGameProcessHost` 明确拒绝；Linux/Windows Java、natives、路径权限、安装与图形游戏世界端到端验收尚待补齐。
- 平台组合根的凭据选择已接入；其余窗口桥接、打包、OS 集成与对应能力声明仍需按功能逐项适配，不把“工厂返回正确对象”当作全部平台完成。

建议下一步处理 Windows 游戏进程独立运行与日志重定向，再分别执行 Windows/Linux 官方 Java/原版游戏链路。登录和皮肤实测需用户在微软页面完成授权；无需开发者在源码里写入账号密码。
