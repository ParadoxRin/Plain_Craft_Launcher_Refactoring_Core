## 源码与环境

```bash
git clone https://github.com/ParadoxRin/Plain_Craft_Launcher_Refactoring_Core.git
cd Plain_Craft_Launcher_Refactoring_Core
git status --short
git log --oneline --decorate -8
```

仓库已公开；从清理后的0.36.1历史继续，不导入旧PCL_Mac的Git对象。Release源码ZIP不带Git历史，需历史时克隆仓库。参考[交接Prompt](开发交接Prompt.txt)和[AI开发责任](开发方式与责任.md)。

本次打包支持Apple Silicon、macOS14+、Xcode Command Line Tools、Python3、curl。SDK固定为global.json的10.0.402；Windows/Linux通用核心是目标，已有三系统核心CI通过证据；完整平台适配、签名及Host/游戏运行验收尚未交付。

```bash
bash scripts/build-handoff.sh
```

脚本会准备SDK、编译原生桥、校验固定LWJGL Agent，并发布自包含Desktop/Host。可用DOTNET指定已有同版本SDK。首次还原需要网络；发布脚本会自动还原并复用本地NuGet缓存。SDK就绪后，也可先单独还原以诊断网络/依赖问题：

```bash
export DOTNET_CLI_HOME="$PWD/.cache/dotnet-home"
./.tooling/dotnet/dotnet restore src/Pcl.Desktop/Pcl.Desktop.csproj -r osx-arm64
```

版本由release.json读取，并核对Desktop项目Version；0.41.0输出同版本.app和macOS-arm64.zip。使用ad-hoc签名，未进行Developer ID公证。ZIP通过ditto保留.NET文件签名扩展属性，解压后再次校验签名、文件哈希和执行权限。原生dylib install_name应为@rpath/libpclwindow.dylib。

输出目录必须全新，项目是控制台测试程序，不能把dotnet test未报错当成实际执行。0.41.0发布收尾为231/231；main的Windows修复后本地Mac及三平台CI均报告235/235（提交497cdd1，运行40444961793），只证明该套件范围。历史22项Iris与38项事务可按改动选择：`--iris036`、`--txn035`。Fabric规划使用`--planning037 <输出目录> <Java路径> <Fabric Loader 0.19.5 JAR>`，HTTP为fixture，Java解析器为真实加载器。

| 证据层级 | 能证明 | 不能代替 |
|---|---|---|
| 编译/架构守卫 | 引用、符号和语法边界 | 功能运行、全平台支持 |
| 规则/文件/HTTP fixture | 成功拒绝、取消、回滚等指定语义 | 真实服务、账号和网络兼容 |
| 真实Host/UI | 实际入口、状态、文件和进程行为 | 人工视觉、世界保存 |
| 真实游戏菜单 | 启动、Java/native和渲染初始化 | 长时稳定性、世界/存档验收 |
| 世界与人工确认 | 指定组合的图像、标记、保存与重进 | 所有版本、平台或模组组合 |

## 最终包与平台测试

Workspaces真实流程可指定发布Host：

```bash
export PCL_HOST_TEST_EXE="$PWD/artifacts/Plain Craft Launcher Refactoring 0.41.0.app/Contents/MacOS/host/Pcl.Host"
./.tooling/dotnet/dotnet build tests/Pcl.Workspaces.Tests/Pcl.Workspaces.Tests.csproj -m:1 -nr:false
```

先读Program与具体Flow。`--closeout-link`运行官方EasyTier模块与两个本地节点；`--closeout-workspace`需要已准备的隔离共享缓存。游戏/皮肤/微软测试要准备自身有权使用的隔离数据。新源码包不带个人世界、Java和Minecraft资产。密码或验证码只在系统/微软页面输入，真实密钥不写入聊天或日志。

关于页探针使用`--license0361-smoke --data-root <隔离目录> --remote-report <JSON>`，新根需`.license-ui-test`标记且目录名为license-ui-data。它验证真实窗口和Host劝导，不进行微软授权或游戏启动。

`scripts/test-closeout-java-host.py`支持`PCL_HOST_TEST_EXE`指向最终包Host；其菜单测试需要`.closeout-fifth`隔离标记及已安装版本，退出是探针停止，不算保存退出。窗口退出探针支持`PCL_DESKTOP_TEST_EXE`指定最终包程序。所有测试只清理自身创建的进程，不执行“杀掉全部Java”。

## 变更与发布流程

1. 选择用例/矩阵ID，读v1.5.1规范、来源许可和已有边界；vendor修改先读其AGENTS。
2. 在Host实际执行路径实现，不在Shell复制业务。保持凭据、独立进程、事务与单一释放责任。
3. 做与本次改动相称的编译和测试，失败先分析；将实际来源、未执行范围写入报告。
4. 更新release.json、Desktop版本、当前文档与交接Prompt；不批量改写历史报告。
5. 生成最终应用并验证关于页、Host、签名、dylib与必要游戏行为。应用内资源在签名前完成，不在签名后修改包。
6. 扫描待提交源码与发布包。`audit-release-privacy.py`为模式扫描；`audit-repository-privacy.py`检查Git历史，公开client ID以授权白名单处理。未知秘密及任意模组配置仍需审查。
7. 人工审查/验收责任按开发方式记录；提交后用`package-source.py --ref HEAD`生成准确源码快照，再附校验和上传Release。源码包仅含Git提交，不含未提交修改。
8. 核对远端提交、标签、附件大小与哈希。无Windows/Linux实机证据时不发布对应“已验证”声明。

仓库已配置 [Core CI](../.github/workflows/core-ci.yml)：三系统编译后实际运行控制台测试，不执行 Mac 打包、真人认证或游戏世界测试；逐次结果见 [Actions](https://github.com/ParadoxRin/Plain_Craft_Launcher_Refactoring_Core/actions/workflows/core-ci.yml)。最终六项修复、235/235报告及重现边界见[Windows CI修复验收](Windows-CI六项修复与验收.md)；初次失败保留在[CI与文档一致性核对](CI与文档一致性核对.md)。已发布包的历史结果仍见[0.41.0发布记录](0.41-核心平台定位与发布.md)，不由后续 CI 自动更新。
