# 开发与验证

## 获取源码

本仓库是私有项目，访问需要仓库所有者授权。克隆后保留真实历史与标签：

```bash
git clone https://github.com/ParadoxRin/Plain-Craft-Launcher-Refactoring.git
cd Plain-Craft-Launcher-Refactoring
git log --oneline --decorate --all
git status --short
```

本仓库从0.36.1单个初始提交开始，标签`v0.36.1`。不恢复或合并旧仓库历史及旧bundle。旧技术记录仅作参考，历史证据路径可能不随清洁基线交付；当前验收见0.36.1报告。

## 环境与构建

Apple Silicon、macOS 14+、Xcode Command Line Tools、Python3和curl。SDK固定为`global.json`里的10.0.402。

```bash
bash scripts/build-handoff.sh
```

脚本执行原生桥接构建、LWJGL agent校验与当前Desktop/Host发布。没有私有SDK时会下载校验官方SDK；已有SDK可通过`DOTNET=/absolute/path/to/dotnet`指定。下载和NuGet还原需要网络。

生成`artifacts/Plain Craft Launcher Refactoring 0.36.1.app`。构建自动执行架构守卫，签名为ad-hoc，未公证。现有AVLN3001为MainWindow构造注入提示，不要通过全局单例绕开它。

仓库没有配置自动Actions工作流，也不会因阅读本说明而消耗云端构建额度。添加CI需单独选择支持平台、缓存、权限和真实/替身测试范围。

## 最小定向验证

从源码根目录运行，输出目录必须全新：

```bash
export DOTNET_CLI_HOME="$PWD/.cache/dotnet-home"
./.tooling/dotnet/dotnet build tests/Pcl.Tests/Pcl.Tests.csproj -m:1 -nr:false
./.tooling/dotnet/dotnet tests/Pcl.Tests/bin/Debug/net10.0/Pcl.Tests.dll --iris036 artifacts/receiver-iris-tests
./.tooling/dotnet/dotnet tests/Pcl.Tests/bin/Debug/net10.0/Pcl.Tests.dll --txn035 artifacts/receiver-resource-tests
```

外部SDK用户替换可执行文件路径。新工作区尚未还原时不要先用`--no-restore`。

| 测试层级 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 编译/ArchitectureGuard | 语法、项目引用与符号约束 | 业务实际成功 |
| 22项Iris定向测试 | 文件归属、依赖、冲突、进程中断恢复；HTTP为替身 | 公共源网络与游戏画面 |
| 38项相关事务测试 | 配置/资源/组件的定向行为 | 全功能回归 |
| 真实Client/Host/UI | 协议、按钮、状态与实际执行链 | 用户世界视觉确认 |
| 真实游戏与人工确认 | 指定组合的启动、保存、重进及观察结果 | 所有游戏版本、所有Mac或长期稳定性 |

## 真实Host和游戏测试

先构建并设置最终包的Host：

```bash
export PCL_HOST_TEST_EXE="$PWD/artifacts/Plain Craft Launcher Refactoring 0.36.1.app/Contents/MacOS/host/Pcl.Host"
./.tooling/dotnet/dotnet build tests/Pcl.Workspaces.Tests/Pcl.Workspaces.Tests.csproj -m:1 -nr:false
```

然后阅读[Workspaces测试入口](../tests/Pcl.Workspaces.Tests/Program.cs)和对应Flow。`--iris036-world`需要隔离数据根、输出目录和世界来源，`--iris036-uninstall`需要已准备的共享或独占环境。相关UI模式同样有根目录与实例检查。源码仓库不带个人世界、Java、Minecraft资产和旧运行目录，不能照抄历史绝对路径。

微软实测入口见[DesktopHost.Live](../tests/Pcl.DesktopHost.Live/Program.cs)。它要求接手者自己的可用账户；钥匙串提示在系统窗口处理，不把密码、验证码和令牌写进聊天或日志。没有第二个账户时将切换场景标为未执行，不伪造结果。

游戏独立运行测试见[verify-detached-package.py](../scripts/verify-detached-package.py)，运行前阅读其数据准备和进程清理行为。它会停止本次拥有的测试进程，只对可丢弃副本使用。不要读取含令牌的完整进程命令行，也不要批量终止所有Java进程。

## 变更、证据与发布

1. 新建工作分支，选定矩阵ID与本轮可交付范围。
2. 读取[架构规范](architecture/PCL-Mac架构规范.md)及相关用例；vendor修改先遵循其AGENTS说明。
3. 修改Host中的真实执行路径，保留Contract边界及原安装/凭据/进程所有权。
4. 按风险运行必要编译与定向测试；新增恢复/删除逻辑覆盖失败、取消、冲突和中断。
5. 对需要平台证明的行为运行实际流程，保存版本、输入、输出与范围。正常退出0和测试主动停止137必须区分。
6. 新增版本证据，不覆盖旧报告或修改旧哈希；对未测试/受外部条件阻塞部分如实说明。
7. 更新支持范围和剩余清单，不添加矩阵子进度、不靠分类调整关闭缺口；保留原作者赞助与正版购买劝导，不做赞助解锁。
8. 按用户要求提交、发布；新版使用独立版本号和产物路径，核对签名、压缩包及解压内容。私有仓库推送不等于已完成公开分发或公证。

## 数据边界与已知限制

`.gitignore`排除runtime、缓存、SDK和生成目录；精选证据与两个必要小构件已显式跟踪。后续不要使用`git add -f artifacts`整体提交测试数据。每次检查实际暂存清单，排除账户、令牌、存档、临时授权截图与包含秘密的配置。

原作者应用标识已移除，开发者需先按[微软登录开发配置](微软登录开发配置.md)提供自己的应用client ID，再用自己的微软账号验证。原作者钥匙串与登录会话不在仓库中。离线账户与微软验证是两条现有路径，不能按旧版申请文档删除当前离线启动行为。

Iris旧环境归属、自定义依赖覆盖、Oculus环境卸载、完整Quilt/TOML语义、部分第三方包和线上自动更新等仍待开发；具体见[剩余清单](0.36-剩余清单.md)。
