## 版本安装、下载和Java

用户在UI选择实例/版本后，经Contract/Client提交Host操作；应用服务管理受理、幂等键、取消和状态，适配器复用现有安装执行链。元数据、下载校验、Java选择和最终实例写入不留在页面里。

| 能力 | 实现入口 | 实现方式与边界 |
|---|---|---|
| 安装受理与恢复 | [InstallOperationService](../src/Pcl.Application/Operations/InstallOperationService.cs)、[InstallOperations](../src/Pcl.Core/InstallOperations.cs) | 用operationId跟踪任务、receipt记录阶段，重开后校验；不同安装器不是同一种恢复语义 |
| 安装执行 | [VersionInstaller](../src/Pcl.Core/VersionInstaller.cs)、[ExistingVersionInstaller](../src/Pcl.Core/Adapters/Operations/ExistingVersionInstaller.cs)、[LoaderOperationInstaller](../src/Pcl.Core/Adapters/Operations/LoaderOperationInstaller.cs) | 继续复用原版/加载器流程，不为每个窗口重写；旧Forge仅部分格式受支持 |
| 下载与续传 | [DownloadService](../src/Pcl.Core/DownloadService.cs)、[DownloadTasks](../src/Pcl.Core/DownloadTasks.cs)、[SegmentedDownload](../src/Pcl.Core/SegmentedDownload.cs) | 临时文件、校验、受控提交，已有并发分段和块复用；不等于Windows原版全部动态调度 |
| Java匹配与发现 | [JavaService](../src/Pcl.Core/JavaService.cs)、[JavaDiscovery](../src/Pcl.Core/JavaDiscovery.cs) | 根据元数据和目标环境选择/检查Java；ARM64原生库、实际Java进程需独立核对 |

免登录下载/安装是产品行为，不能因为微软API暂不可用而一并禁止下载。支持某加载器入口不代表它的全部构建及模组组合已通过世界验收。

## 账户、皮肤和启动

微软路径通过设备码授权，再处理Xbox/Minecraft身份及权益；凭据经IAccountSecrets留在Host和系统钥匙串。离线账户独立管理，不能把离线启动状态当作微软正版验证结果。

| 能力 | 实现入口 | 关键约束 |
|---|---|---|
| 账户状态与登录执行 | [Accounts](../src/Pcl.Core/Accounts.cs)、[HostAccountService](../src/Pcl.Application/Accounts/HostAccountService.cs)、[WorkspaceAccounts](../src/Pcl.Core/Adapters/Pages/WorkspaceAccounts.cs) | UI提交操作并取可显示状态；不接收原始令牌 |
| Mac凭据 | [KeychainAccountSecrets](../src/Pcl.Core/Adapters/Mac/KeychainAccountSecrets.cs)、[MacAccountSecrets](../src/Pcl.Core/MacAccountSecrets.cs) | 沿用IAccountSecrets，不把刷新令牌放进设置、日志和receipt |
| 皮肤 | [PublicPlayerSkin](../src/Pcl.Core/PublicPlayerSkin.cs)、[OfflineSkinService](../src/Pcl.Core/OfflineSkinService.cs)、[MicrosoftSkinService](../src/Pcl.Core/MicrosoftSkinService.cs) | 玩家名获取、图像校验/规范化、保存刷新及导出；二维展示不等于3D人物预览 |
| 统一游戏受理 | [GameLaunchOperationService](../src/Pcl.Application/Operations/GameLaunchOperationService.cs)、[LaunchService](../src/Pcl.Core/LaunchService.cs) | 幂等受理、启动前事务/依赖检查、游戏句柄及退出跟踪；窗口关闭与独立运行分离 |

真人账户、皮肤及外置认证支持以 [支持范围](支持范围.md) 为准；代码入口存在不代表全部组合已验收。

## 模组、搜索与整合包

浏览器查询和安装执行经工作区接口进入Host。查询结果是展示数据，下载前Host重新取得版本计划并校验；不能直接信任UI提交的任意下载地址或删除列表。

| 能力 | 实现入口 | 当前限制 |
|---|---|---|
| 浏览与资源执行 | [WorkspaceCatalog](../src/Pcl.Core/Adapters/Pages/WorkspaceCatalog.cs)、[WorkspaceBrowser](../src/Pcl.Core/Adapters/Pages/WorkspaceBrowser.cs)、[ResourceInstaller](../src/Pcl.Core/ResourceInstaller.cs) | 目录查询、版本选择、依赖安装和受管理清单；商店身份不按同名猜测 |
| 多源搜索 | [WorkspaceSearch](../src/Pcl.Core/Adapters/Pages/WorkspaceSearch.cs)、[UnifiedSearchSession](../src/Pcl.Core/Adapters/Search/UnifiedSearchSession.cs) | 有界会话及选择记录；百科本地索引不等于站点实时下载，CF在线路径仍需密钥条件 |
| 依赖规则 | [ResourceDependencyPlanner](../src/Pcl.Core/ResourceDependencyPlanner.cs)、[FabricModPlanner](../src/Pcl.Core/FabricModPlanner.cs)、[QuiltModPlanner](../src/Pcl.Core/QuiltModPlanner.cs)、[JointResourcePlanner](../src/Pcl.Core/JointResourcePlanner.cs) | 三入口通过同一多根候选规划与实际JAR校验；Fabric schema 0/1和version 1覆盖已实现；Fabric嵌套硬约束求解已实现；Quilt自定义插件/虚拟多父路径、可选候选软权重与语言插件仍有缺口，超预算是未判定 |
| 自定义包元数据 | [CustomPackMetadata](../src/Pcl.Core/CustomPackMetadata.cs)、[PackMetadataCompatibility](../src/Pcl.Core/PackMetadataCompatibility.cs) | 支持限定schema与组件描述；不运行任意包内脚本，不承诺所有第三方字段/继承链 |
| 数据包 | [DataPackService](../src/Pcl.Core/DataPackService.cs) | 按目标世界安装；文件操作测试不等于游戏内行为验收 |

mrpack/HMCL/MultiMC/MCBBS等格式必须按各自矩阵条目判断支持范围。升级为新副本可以保留用户改动，但尚不等于对双方修改同一配置进行完整语义三方合并。

## 光影的三个不同操作

1. **撤销应用配置**：[ActivationTransaction](../src/Pcl.Core/ActivationTransaction.cs)记录原/新配置及哈希，通过持久化意图与原子替换恢复。不是卸载ZIP或环境。
2. **卸载受管理光影包**：[ShaderRemovalTransaction](../src/Pcl.Core/ShaderRemovalTransaction.cs)整批检查清单归属和哈希，备份后移除受管理ZIP，保留用户文件与环境。
3. **卸载Iris环境**：[IrisEnvironmentService](../src/Pcl.Core/IrisEnvironmentService.cs)结合安装前归属、实际JAR依赖与[ResourceOwnership](../src/Pcl.Core/ResourceOwnership.cs)用途记录，只删除可以独占移除的组件。

[IrisEnvironmentWindow](../src/Pcl.Desktop/IrisEnvironmentWindow.cs)显示移除/保留/冲突集合，确认后Host仍重验计划。运行中的游戏会阻止资源变更；恢复遇到新增依赖或损坏备份会停止并阻止启动。

共享依赖保护和文件事务需要对应测试；历史渲染结果不替代本次修改后的实际验证。旧环境无可信记录和Fabric依赖覆盖配置仍明确拒绝自动卸载，Oculus环境卸载未实现。

## 修改与验证顺序

先定位下表对应功能，再查看具体 Contract、Host 分发和执行路径。支持范围以现行矩阵/发布记录为准；本页是代码导航，不是历史验收结论。

1. 明确用户行为与失败、取消边界。
2. 判断修改属于 UI、协议、编排、规则还是外部适配；按 [接口分类](公共接口与内部实现.md) 保持引用方向。
3. 优先复用已有任务和事务；新增方法检查资源冲突、恢复记录与能力协商。
4. 按 [测试指南](测试指南.md) 验证真实入口；跨平台/真人账号/世界验收单独记录。
