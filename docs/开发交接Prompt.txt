你接手的是 Plain Craft Launcher Refactoring Core。当前发布为 0.41.0 Preview；main 含发布后的文档、CI 和维护改动。公开仓库：https://github.com/ParadoxRin/Plain_Craft_Launcher_Refactoring_Core 。应用显示名为 Plain Craft Launcher Refactoring，Git/隐私基线从 v0.36.1 开始。复现发布包检出 v0.41.0；继续开发使用 main，并记录实际提交。不要把 main 的后续改动写成已包含在既有安装包中。

一、目标和现状
目标是供 macOS、Windows、Linux 复用的启动器核心，让开发者自行选择 UI 组件库、布局和语言制作客户端。已交付 Apple Silicon Mac 的 Avalonia 参考客户端及独立 .NET Host。SwiftUI 是 Mac 原生参考方向，尚未实现；Windows/Linux 客户端尚未实现，对应平台适配仍待补齐与验收。无需先完成三套 UI 才能交接核心，也不因目标变化删除既有功能缺口。不要未经要求重写全部 UI。

先读 README.md、docs/architecture/PCL-Mac架构规范.md（现行 v1.5.1）、docs/架构与设计取舍.md、docs/客户端接入指南.md、docs/功能实现导览.md、docs/剩余清单.md、docs/architecture/技术债.md，以及本轮用例的源码和证据。docs/0.41-核心平台定位与发布.md 是固定发布记录；docs/CI与文档一致性核对.md 记录其后的核对与云端结果。规范约束、源码现状、运行证据是三件事。

三、实际架构
Desktop -> Client + Contract；Client -> Contract；Host -> Application + Core + Contract；Application -> Domain + Ports + Contract；Ports -> Domain；Core -> Domain + Ports + Contract + 上游库。Domain/Contract 不引用其他项目。Adapters 仍在 Core 中，Core 不引用 Application。Desktop 的 Host/ArchitectureGuard 引用仅为构建依赖，不是运行时业务引用；Bootstrap 没有业务例外。

CLI 仍有 Core/Application/Client 直接引用，是遗留技术债，不是新 Shell 的模板。六种职责不等于六个同名程序集；Pcl.Core.Contracts 命名空间可能属于独立 Contract DLL。当前真实图见架构文档，规范的目标图不能当作全部已实现。

Host 持有组合根、数据根 OS 独占锁和执行/关闭责任。Application 编排，Domain 纯规则且不引用 Ports；外部数据经应用层取得后显式传入。继续复用 InstallOperations -> VersionInstaller 与 ResourceDependencyPlanner，不在 UI 另写安装、下载、求解或 Java 匹配。Core 内部按用例进一步整理，不恢复已移除的 Desktop 业务引用。

四、协议接入
当前是 PCL 自定义 RPC v1 / UTF-8 NDJSON，不声明 JSON-RPC 2.0 兼容。Desktop 默认使用当前用户私有命名管道：先 session.attach（客户端 GUID、PID 与创建时间），再 host.hello；stdio 直接 hello，仅为直接进程/测试路径。照 HostClient、PrivatePipeServer、SessionOwner 与 SharedProtocol 实现身份及权限，不能直接开放 TCP。

请求 ID 使用每连接随机 GUID 前缀 + 冒号 + 从 1 连续递增序号，在发送锁内分配；重连换前缀。hello 返回能力、帧上限、Host 身份和安装目标。version.install 的 params 是 InstallCommand，含 idempotencyKey 和嵌套 installation（gameVersion/loader/target）；不要照旧文档扁平参数发送。安装操作契约 v3 不等于 RPC 版本 3。

事件使用 event.changed + HostEvent（subscriptionId/hostId/kind/subjectId/sequence/snapshot）。先注册本地缓冲再 event.subscribe，随后取快照并按水位合并。请求 ID、operationId、幂等键分别管理。网络超时不代表操作已停；先查询原操作，不能换键重复副作用。

统一幂等受理适用于 version.install/game.launch/page.begin；account.login.begin 使用 key/remember，有独立 LoginSnapshot，重启中断为 LOGIN_INTERRUPTED。外观修改等入口不承诺通用持久化重放，先查询而非自动重发。当前 RPC 错误仅 error.code，不能依赖尚未实现的通用 detail/retry 字段。

会话恢复是连接同一 Host 查状态；安全续做是新 Host 校验 receipt/文件/提交后建立新尝试。支持的加载器安装已有恢复路径，资源/整合包不支持任意位置续做。未知提交拒绝盲重放。当前没有稳定 Swift SDK、通用 C ABI 或任意插件系统。

五、必须保持的行为
免登录下载；微软和离线身份分开；账户/皮肤持久化；数据根、bundle 与钥匙串标识；托管/独立游戏生命周期；窗口取消与后台操作取消分离；单一释放；文件归属、哈希、依赖与事务保护。Forge 单人 Quick Play 拒绝、Iris 未知归属及自定义覆盖卸载拒绝等现有限制不能删掉冒充支持。

IAccountSecrets 沿用。微软 access/refresh token 与轮询 DeviceCode 留在 Host，不返回 UI，不进入 receipt、设置导出或日志。用户可主动在 UI 输入第三方 API Key/外置认证密码，经专用私有 workspace.secret 交给 Host 短时内存，后续只传句柄；这不授予读取系统凭据或回传微软令牌的能力。普通模组配置可能自带秘密，导出检查不能保证识别全部未知字段。

OAuth 自 0.40.1 起内置应用所有者授权的公开 client ID，普通用户登录自己的微软账号。公开 ID 不是 secret；不上传密码、刷新令牌、client secret 或个人租户资料。独立发行者可配置自身有权使用且获准的应用 ID，见微软登录开发配置.md。不要采用旧“默认空 ID”说明。
