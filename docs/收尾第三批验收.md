# 收尾第三批验收：隐藏恢复、帮助、本地扫描、Java 发现

日期：2026-10-27。基于 0.40.1 后的本地源码构建，未替换已发布包。实际运行结果见 [收尾第三批验收结果.json](收尾第三批验收结果.json)。

## 本轮修复

1. 帮助页输入框称“搜索帮助内容”，实际只匹配文件名。现同时匹配文件名和正文，忽略大小写；结果按文件名稳定排序。
2. 帮助查询变更后可能留下旧正文。现重置选择并清空正文，单文件读取失败不阻断整个检索页。
3. “隐藏 Mod 更新”未传递给本地资源窗口。现窗口打开时从 Host 读取外观设置，并将检查、安装、批量更新及“忽略此版本”纳入同一隐藏规则。恢复后重新打开窗口可见。

隐藏是界面偏好，不是权限隔离；不禁止 Host API 执行相关功能。没有借此改动登录、皮肤、游戏进程或安装流程。

## UI-005 功能隐藏与恢复

真实 Avalonia 个性化页面的 22 个开关全部勾选，通过“保存设置”写入 Host；重新读取快照逐项核对。主导航页签与版本管理／修改按钮隐藏，恢复入口保留。本地资源窗口的更新按钮隐藏。点击实际“恢复界面”按钮后，Host 隐藏配置清空，主入口恢复；重新打开本地资源页后更新操作恢复可见。

该项验收范围为 22 个开关的真实保存和代表性主入口／资源动作的隐藏恢复；未声称人工检查每个页面像素，也不把隐藏解释为安全访问控制。

## UI-006 帮助检索

真实帮助页用 `client secret` 查询已有文档正文，选择结果后显示匹配正文；不存在的关键词返回零项并清空旧正文；文件名查询与清空查询恢复列表通过。使用仓库实际文档，不替换帮助内容或伪造搜索结果。

前两轮探针在 Avalonia TextChanged 完成前检查旧列表，断言失败。最终探针在赋值后等待界面事件处理，再检查列表和正文；保留失败报告，不把探针时序修改当作额外业务修复。业务修复见上节。

## RES-014 本地外部资源扫描

隔离实例内共 10 个文件：

- 七份合成元数据样本：Fabric、Quilt、Forge TOML、NeoForge TOML、旧 mcmod.info、LiteLoader、停用 Fabric 文件。
- 两份上一批已按官方 SHA-1 核对的公开模组：Fabric API 0.102.0+1.21.1、Mod Menu 11.0.1。
- 一份故意损坏的 JAR。

真实 Host 扫描全部文件，逐个核对模组身份；损坏文件单独给出错误，其余扫描不受影响。实际资源页面的“已停用”“异常文件”筛选分别只显示正确的一项。

这是磁盘 JAR／ZIP 读取、元数据识别与 UI 筛选验收；合成文件不含可运行模组代码，不能当作加载器启动、依赖求解或所有历史格式兼容验收。复杂依赖相关矩阵缺口保持原状。

## JAVA-008 已安装 Java 的发现和排序

Host 实际运行已有官方 ARM64 Java 8、17、21、25 的检查命令，核对主版本和 aarch64 架构。重复候选去重，跳过 macOS `/usr/bin/java` 安装提示 stub；本机架构的有效运行时按主版本降序排列。

本次进程的 JAVA_HOME 指向已有 Java 21；实例页面“全局启动设置 → 查找已安装 Java”找到它，实际列表选择后使用并保存，Host 快照确认选择已持久化。仅设置测试进程环境变量，没有修改用户系统环境或默认游戏配置。

另运行定向候选测试：启动器 runtime receipt 解析、重复路径去重、路径越界 receipt 拒绝和系统 stub 排除通过。此测试的 receipt 使用普通文件夹具，不将它称为真实 JVM 启动；真实 JVM 检查由上面的四个实际运行时提供。

未验证 Intel／Rosetta、Java 16、所有第三方 Java 管理器目录或用这些选择再次进入 Minecraft 世界。JAVA-007 的手动文件选择器及游戏启动全链路仍保留待验收。
