# PCL Mac 0.31：主窗口与联机执行迁移

本版沿用架构规范 v1.2 的分阶段迁移及后续已落盘修订。保留 Avalonia、现有安装器、账户存储和游戏托管策略；新增的默认执行路径为 Shell → Contract → Client → 独立 Host。Desktop 对 Core 的依赖尚未全部移除。

## 实现范围

- 主窗口版本列表和下载对话框使用 `MinecraftRelease` 契约数据；原版安装仍调用既有安装契约。加载器查询、选定版本安装、Java 准备和 Mac 基础/光影配置由 Host 执行，沿用原安装器与校验流程。
- OptiFabric 窗口只负责选择文件、输入、进度和取消；Host 校验固定文件并创建兼容实例。文件校验与安装期间都持有界面生命周期，任务未结束不能直接关闭。
- 微软登录统一通过 `IAccountLogin`；默认实现是既有 `LauncherSession` 登录流程。原钥匙串与会话账户逻辑未改，显式 `--in-process` 调试模式的实现放在 Core/Adapters，不由 MainWindow 构造认证器。移除主窗口未使用的 Java/父版本准备方法和启动钩子执行器。
- 联机窗口只依赖 Contract/Client。EasyTier 进程、节点查询、断开和 Host 退出清理由 Host 持有；关窗请求取消、等待当前任务，再断开该窗口持有的房间。同一 Host 的客户端重连保留房间。
- 游戏运行期间只额外允许联机 start/status/stop 三个命令；兼容写入授权仍保持撤销。其他设置、安装、账户修改不因此绕过游戏运行保护。断开联机不停止 Minecraft。
- 邀请码经独立私有 RPC 读取，加入时通过一次性内存凭据句柄传入；任务 receipt 和公开结果不携带房间秘密。Host 重启不会自动重建房间，旧会话查询返回停止，需重新连接。
- 新增联机与 OptiFabric 页的编译后符号守卫，并约束主窗口已迁移的下载、加载器、Mac 配置和登录处理器不得重新调用旧执行器。仍保留旧展示模型与 Bootstrap 桥接的明确例外。

最后一次构建只移除主窗口未使用的方法、修订注释与内嵌架构矩阵；`microsoft-host-code-continuity.json` 确认 Host 可执行文件及 184 个 DLL 未改变。变更后的 Desktop 另做最终包界面、托管与独立运行测试。

微软复测结束后，测试游戏与 Host 已退出，原数据目录独占锁可重新取得，记录见 `release-cleanup.json`。此次游戏由测试主动停止，渲染初始化不等于人工进入世界、保存及重新进入验收。报告完成后只更新包内文档和外层签名；`tested-code.json` 中 397 个代码文件保持不变。最终 ZIP 解压逐文件核对与签名结果记录于 `delivery.json`。

## 保留的限制

- DEBT-002 未关闭：MainWindow 的旧展示模型、其他旧窗口/测试入口及 Bootstrap 仍依赖 Core，兼容写入授权仍在。未删除 Desktop → Core 引用，也不声称所有功能与 Windows PCL2 一致。
- 新工作区写入使用已有持久化任务、取消和状态订阅，但未知提交状态拒绝盲目重放；这不等于任意加载器安装都具备自动崩溃续做能力。
- 联机仅验证本机两个真实节点和 TCP 转发；未测试跨互联网、实际两位玩家、UDP 游戏数据或游戏内存档操作。无 TUN 模式下原始 ICMP 套接字可能提示权限不足，TCP 转发实测通过；不请求管理员权限解决无关 ICMP 提示。
- 无第二个微软账户、额外外置账户或 CurseForge 密钥。本次不修改在线皮肤、披风，不注销原有微软账户。Mac 光影配置已接线到原流程，本轮实际安装的是基础配置，未重新进行世界内光影验收。
- Apple Silicon 自包含包仅 ad-hoc 签名，未进行 Developer ID 公证。历史包、失败证据和原用户数据保留；原数据启动脚本显式指定原有数据根目录。

联机实现参考官方 [无 TUN 网络说明](https://easytier.rs/en/guide/network/no-root) 与 [端口转发说明](https://easytier.cn/en/guide/network/port-forward.html)，复用已有固定 EasyTier 2.6.4 下载及哈希验证。
