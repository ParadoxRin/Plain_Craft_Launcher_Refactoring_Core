# 0.42.1 本地统一发布、数据自动更新与缓存清理

本阶段保持应用版本 **0.42.1**，客户端 build / 序号 **424**，Host 序号 **42102**，内置数据发布序号 **42102**。核心基线仍为 `81016b476e8811ecbfbd3f969d143b646ac5282d`。新增 Host 数据更新适配和内容缓存清理属于显式差异：`release.json.contentIntegration` 对八个适配文件分别记录上游与当前哈希；其他核心文件保持基线检查。没有推送 GitHub 或上线更新源。

## 统一发布

新增 `scripts/build-unified-release.sh /absolute/fresh-output`，依次构建数据包、独立客户端与 Host、签名清单、完整安装器，最后验证实际交付。输入环境变量：

| 变量 | 内容 |
|---|---|
| `DOTNET` | .NET SDK 绝对路径 |
| `PCL_PUBLISH_KEY` | 位于资产目录外的发布者私钥路径 |
| `PCL_PUBLISH_BASE_URL` | 本次不可变 HTTPS 资产目录（应包含 build/序号） |
| `PCL_HOST_FEED_URL` | 稳定 Host feed 地址 |
| `PCL_CLIENT_FEED_URL` | 稳定纯客户端更新清单地址 |
| `PCL_APP_FEED_URL` | 稳定完整 `.app` 更新清单地址 |
| `PCL_CONTENT_FEED_URL` | 稳定的已签名数据包 JSON 地址 |

四个稳定地址必须分别配置。纯客户端和完整 `.app` 使用不同清单，防止安装类型混用。客户端更新策略在打包/代码签名前注入；统一索引记录两个客户端包的签名清单、数据地址及包哈希。验证工具既使用调用方提供的独立公钥，又检查包内固定公钥、清单、序号和实际 ZIP 字节一致。

`component-publisher.yml` 已接入这个统一入口，生成待审核附件；仍不创建公开 Release、不覆盖线上 feed。`component-packages.yml` 增加客户端自更新与数据/清理验收。正式发布还需发布者配置密钥及真实托管地址，并先验证不可变资产，再切换稳定 feed。本轮只在本地运行，不把工作流代码视为远端 CI 已通过。

Host 最低序号允许在客户端候选包中提高，但拒绝降低；信任公钥、频道和更新地址等其他策略仍须一致。这使后续 Host 序号增长不会被误判为更换信任根。

## 数据自动更新入口

Host 新增 `content.update.v1` 能力及 `content.update.status` / `content.update.begin` 请求。客户端启动及每六小时检查一次，“关于”页提供“检查并安装百科与映射数据更新”。旧 Host 没有此能力时显示不支持，不发送新请求。

Host 使用安装时固定的 `content-update-policy.json`，其中 `FeedUrl` 为可选字段；旧策略没有此字段时不联网。UI 不能传入任意地址、目录或公钥。下载在 Host 后台执行，同一 Host 同时只进行一次；RPC 可继续响应状态和其他操作。HTTPS 禁止重定向，下载限制 16 MiB / 60 秒，先验签、兼容检查和防重放再安装。Host 退出时取消并等待后台任务。

活动索引在 Host 进程中保持不变，界面分别显示当前序号和已安装序号，明确提示下次 Host 启动生效；不会因数据更新强制退出游戏或重启 Host。无更新源、网络失败或错误签名不替换现有数据。现有命令行安装/回退入口继续可用。

## 缓存清理

- 客户端：每次检查更新前尝试清理，“关于”页也有手动清理按钮。只清理超过七天且符合更新器命名规则的下载、helper、请求、就绪记录及同级暂存目录。保留最近两项缓存目录、恢复 helper、最近回退备份及仍由存活客户端持有的待安装请求/下载。存在待恢复事务或另一更新器持锁时拒绝清理。
- 数据：成功安装后清理旧哈希包，只保留当前包和上一回退包；保留高水位、锁和其他文件。清理失败不撤销已验证的安装。
- 两类清理都不进入账户/实例/游戏目录；客户端清理拒绝目录树中的链接，数据清理跳过链接文件。

这是保守的保留策略，不是硬性磁盘配额：七天内缓存、当前待安装包及回退包可能较大。Host 自身版本目录继续使用原有机制，本阶段未新增 Host 缓存清理。

退出回退复测还发现：共享资源已排空后，仅关闭主窗口可能留下客户端进程。正常退出现在在排空后关闭 Avalonia 应用生命周期并显式结束进程，游戏运行时的隐藏策略保持原有行为。

## 验证范围

具体本地结果见[统一更新验收](0.42.1-统一更新验收.json)。验证包含实际签名交付链、实际包内核心回归、独立 Host RPC、真实 macOS 客户端更新/回退，以及后台数据更新和缓存保留/拒绝测试。数据下载使用 HttpMessageHandler 替身验证下载逻辑，不等于正式 HTTPS/CDN 联调。

本机为 macOS ARM64。未执行远端 CI、正式托管更新、真人账户/游戏世界及 Developer ID 公证。常规 `.app` 仍带 Host：本阶段不声称完成完整安装布局迁移，或让完整 `.app` 的界面更新只下载 UI。
