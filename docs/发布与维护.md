# 发布与维护

当前发布目标：0.43.0 / build 428，标签 `v0.43.0`，目标 Apple Silicon macOS 14+。SDK 0.43.0、Host 43000、内容 42102；手动升级，不把相同 Host 序号重新推入自动更新。

## 交付规则

- 用户安装应用与独立 client/Host 分别提供；不发布冗余 full.zip。开发者无需下载全部附件。
- 当前版本手动升级，不注入测试地址、临时公钥策略或个人配置。自更新代码仍可用于独立开发测试，默认未配置不会自动安装候选。
- 构建需使用干净提交，核对数值版本、build、Host probe、权限、许可、ZIP 哈希、签名及隐私扫描。变更已签名包必须重新构建和签名。
- macOS 采用 ad-hoc 签名，未作 Developer ID 公证。发布页必须明确未公证限制，不能写成 Developer ID 签名或已公证。
- 自动测试使用隔离数据目录与合成账户；真实登录验收由用户参与，凭据留在平台凭据库。不把测试结果、截图或交接历史提交回源码。CI 附件设置保留期。

## 每次正式发布前

以下条件需要逐项完成，不能用静态审查或样例编译替代：

1. 在最终候选上完成真实微软交互登录、账户恢复、授权引导，以及真实游戏启动、退出、世界保存与重开验证。历史版本的验收不能自动代替新的登录与并发实现；验收结论记录在对应 Release。
2. 核对正式支持的 Minecraft/Java/加载器组合，说明未支持的外置认证与其他平台，不承诺所有模组兼容。
3. 对最终安装包执行干净安装、已有数据升级、备份恢复和退出行为检查；数据格式变化需要单独迁移与回退设计。
4. 若启用自动更新，配置发布者控制的 HTTPS 地址、持久私钥保管与预置公钥、不可变附件和防重放序号；先验证可下载字节，再切换 feed。否则保持文档明确的手动升级方式。
5. 确定面向普通用户的 Apple 签名/公证分发方案，或明确保留未公证分发限制。没有证书不能把 ad-hoc 写为 Developer ID。
6. 处理阻断级问题；确认当前源代码、标签、安装包及发布说明对应同一候选。

## 长期维护

README 保持当前状态；技术文档保留架构、调用与复现方法。历史结果由 Git 历史和短期 CI 附件承担，不在当前文档目录累积版本日志。保留协议/安全测试、许可、来源说明及编译嵌入的数据文件，不能按名称含“test”或“audit”批量删除功能性代码。

## 已验收运行文件的发布

已发布运行文件以对应 Release 标签中的 `release.json` / `runtimeBuildCommit` 为准。main 可以包含后续维护，分支构建属于候选，不能据此替换现有发布附件。源码标签包含发布元数据与分发说明。最终候选验收后若修改业务代码，必须重新构建并重验受影响行为。发布时比较运行文件，确保没有混入未经验收的业务修改。构建、测试结果和个人游戏数据不进入源码或发布附件。
