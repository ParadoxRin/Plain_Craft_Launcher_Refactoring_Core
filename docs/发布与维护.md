# 发布与维护

当前开发者版本为 **0.44.0 / build 430**，标签 `v0.44.0`；Core/SDK 0.44.0，Host 序号 44000，内容序号 42102。发布身份以根目录 `release.json` 为准。

## 交付内容

- macOS ARM64 轻量 Host：完整后端依赖集合，不携带 .NET 运行时；要求预装 ARM64 .NET 10 运行时或 SDK。
- SDK：匹配版本的 Pcl.Contract 与 Pcl.Client NuGet 包及包内校验清单。
- 源码：发布提交的已跟踪文件；不包含构建缓存、个人配置或运行数据。
- `release-manifest.json` 与 `SHA256SUMS`：组件身份、部署要求和附件完整性信息。

本次不提供新的桌面安装包；参考客户端仍可从源码构建。Host 内部 DLL 整体交付，不支持任意混用版本。轻量包通过手动部署使用，不作为既有自包含 Host 的自动更新候选。默认未配置生产更新源。

## 发布流程

1. 更新版本、build、Host 序号和 SDK 身份，提交后将核心基线固定到对应源码提交，运行基线与模块边界检查。
2. 按[分包构建与签名](分包构建与签名.md)生成 Host 与 SDK；从最终 ZIP 解压运行 Host probe、客户端协议和受影响回归测试，确认外部运行时要求。
3. 核对必需依赖、许可、文件权限、源码来源、隐私扫描和所有附件哈希。签名文件修改后必须重新签名；未经过 Developer ID 签名及公证的产物不能标为已公证。
4. 等待对应提交的 CI 通过，确认标签、源码、包身份和说明一致，再发布不可变附件。发布说明列出交付范围与运行要求，不以核心测试推断完整桌面体验。
5. 启用签名自动更新属于单独部署：配置发布者控制的 HTTPS 地址、持久私钥和预置公钥，验证兼容性、防重放及回退，先验证不可变附件再切换 feed。

涉及账户、游戏启动、桌面交互或数据格式的后续变更，应补充对应集成测试与迁移/回退验证；核心发行不替代客户端自身的产品验证。

## 维护规则

README 保持面向开发者的当前入口，技术文档保留架构、调用约束和复现方法。历史过程记录由 Git 与短期 CI 附件承担，不进入源码或发布包。协议测试、许可、来源清单及编译嵌入的数据文件属于有效项目输入，不能仅按文件名批量删除。

发布包以对应标签为准；main 的后续改动不能用于静默替换既有附件。涉及执行代码的改动必须重建并验证受影响行为。
