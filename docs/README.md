## 文档维护规则

- 新人操作步骤维护在快速开始，测试选择维护在测试指南；详细 API/部署参数维护在开发指南，避免多处复制同一套首次运行步骤。
- 版本和发布身份以 release.json 及对应 Release 为准；协议字段以 Contract 和实际实现为准。修改行为时同步相应操作文档。
- 当前树不保存历史截图、一次性验收输出和交接记录；历史通过 Git 和 Release 查询。新运行结果放忽略的 artifacts/ 或有保留期限的 CI 附件。
- 来源清单、许可、固定兼容数据等即使带历史版本号也可能是构建与溯源输入，不按“旧文档”随意删除。
