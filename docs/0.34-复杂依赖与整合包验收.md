# PCL Mac 0.34：复杂依赖与整合包兼容

## 实际变化

1. **批量更新联合求解**：ResourceBatchUpdater 不再逐根独立选前置。ResourceCatalog.ResolveManyAsync 共用项目版本表，显式根版本锁定；JointResourcePlanner 回溯未锁定的声明前置。每套候选在暂存目录交给现有 ResourceInstaller 和加载器校验，成功后才允许预览/提交，失败、取消均保留现有模组。最多256个已检查状态、每项64个候选、16384个待检查状态；超过限制明确“尚未判定”，不伪称无解。网络/文件错误直接传播；下载完整性失败单独传播，不触发降级回溯。
2. **JarJar模块身份**：按目标Java优先选显式module-info.class，再按Multi-Release主属性选择适用版本；回退Automatic-Module-Name及文件名。处理manifest续行和主段、修改版UTF-8、描述符边界/重复；纯字节解析在Domain，JAR/文件读取仍在Core/Host。Forge/NeoForge嵌套库不同文件名、不同坐标但同显式模块可按既有身份规则去重。不是完整JVM class验证器，也未补完语言插件或所有TOML语义。
3. **自定义整合包入口**：MultiMC声明式组件及HMCL官方基础元数据可附加经过大小/SHA-1校验的库和mainClass；类名、Mac规则和类文件存在/唯一性须通过。保留标准账户参数、Java和natives重建流程。PCL扩展schema2保存入口与有序+tweakers，mrpack导出重导不丢入口；tweakers仅允许LaunchWrapper入口。schema1继续可读，schema2需要PCL Mac0.34+，不声称其他启动器识别该扩展。

入口仍在现有“本地资源→检查更新→批量更新”和“整合包→导入/导出”中，执行位于Host；没有新增空页面或把业务规则迁回Desktop。Desktop仍只运行时引用Contract/Client。沿用IAccountSecrets、既有微软应用ID和游戏退出策略。

## 剩余范围

仍为42项已覆盖限定范围、35项实现缺口、46项定向验收、9项外部条件验收。**本轮完成3组子能力，补强7个部分实现条目；没有把35个大项全部标成完成。** 每项下一步详见 [0.34剩余清单](0.34-剩余清单.md)，历史audit033保留，新证据以audit034及SHA-256关联。

优先待补：Quilt path/pattern/version覆盖，Fabric schema0/覆盖与插件，NeoForge provides/语言插件，整合包锁定清单联合补全、自定义客户端/jarmods/安装器、配置三方合并。+tweakers正向LaunchWrapper游戏本轮未实测；现在仅有解析/拒绝保护证据。没有自动推断它已完整兼容LiteLoader/OptiFine任意组合。

## 交付与官方依据

Apple Silicon自包含应用，ad-hoc签名已验证，未做Developer ID公证。ZIP逐文件解压比较和签名结果见delivery.json；测试进程已清理，数据目录OS锁已重新取得后释放。原0.33包和原数据目录保留。

- [MultiMC JSON Patches](https://github.com/MultiMC/Launcher/wiki/JSON-Patches)：mainClass、+tweakers、组件补丁；官方页面本身声明并非完整规范，故保留受支持字段边界。
- [Java ModuleFinder](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/module/ModuleFinder.html)：模块查找、显式/自动模块身份；本轮另有独立JDK对照数据。
- [JVM class文件规范](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-4.html)：常量池、修改版UTF-8、Module属性结构。
- [NeoForge Jar-in-Jar](https://docs.neoforged.net/toolchain/docs/dependencies/jarinjar/)：内嵌元数据和版本协商；范围求交继续复用已实现路径。
