# 自定义客户端接入指南

目标：使用任意适合的平台 UI 组件，复用 Host 中的安装、账户、资源、实例和启动能力。已有 Avalonia/.NET Client 和[可独立运行的最小命令行客户端](../examples/Pcl.MinimalClient/README.md)作为参考。最小示例不引用 Core，并配有真实 Host 契约验收；这仍不是已发布的 Swift SDK 或 Windows/Linux 完整实现。


## 入口与阅读顺序

1. `src/Pcl.Contract`：请求、结果、事件、稳定 ID、错误及能力。历史命名空间含 Pcl.Core.Contracts，不代表需要引用 Core DLL。
2. `src/Pcl.Client/HostClient.cs`、`HostSubscriptions.cs`、`LauncherSession.cs`：协议、订阅/快照、重连、账户与游戏观察的参考实现。
3. `src/Pcl.Host/Program.cs`、`PrivatePipeServer.cs`、`Composition/HostRuntime.cs`：协议分发、私有会话及资源所有权。
4. `src/Pcl.Desktop/Bootstrap` 和导航/窗口生命周期实现：借鉴接线方式，布局和组件可以替换。

.NET 客户端只引用 Pcl.Contract 与 Pcl.Client；不要引用 Core/Application 来省略 RPC。Swift 或其他语言实现等价的数据映射和传输。现有可独立分发的 .NET SDK 仅封装现有 Contract/Client，构建命令见[项目拆分](项目维护边界.md)。当前尚无跨语言 SDK/schema 生成流水线，应结合 Contract、Host 分发与契约测试核对字段，不能把文档示意当作新增 API。

## 协议与最小链路

现有协议是 PCL 自定义 RPC v1，UTF-8 NDJSON，不声明 JSON-RPC 2.0 兼容。每帧单行，帧大小和能力以 hello 返回为准；Host stdout 专用于协议，stderr 为诊断。桌面默认私有管道，stdio 用于直接进程接入/测试；完整重连需要实现私有会话身份和 attach，不是重新启动一个写同一数据根的 Host。

stdio 模式先发送下列 hello。默认私有管道模式必须先 session.attach（ClientIdentity 的 clientId/processId/startedUtcTicks，以及 Linux 上必需的 linuxStartTicks），收到 attachment 后再发送 hello，不能颠倒。握手与请求 ID 的完整约束见[架构规范 §7](architecture/PCL-Mac架构规范.md#7-命令与进程外协议)。

Linux 的 `linuxStartTicks` 是 `/proc/<pid>/stat` 第22字段的原始无符号整数（开机以来的时钟 tick），不是 UTC ticks，也不是毫秒。Host 精确比较此值，缺少/错误时拒绝，不按 PID 或时间容差回退；Client 和 Host 必须一同更新。`startedUtcTicks` 仍保留 UTC .NET ticks 的原含义，Windows/macOS 继续精确校验此字段。旧 Linux 客户端仅发送 UTC 值的握手不再被接受，私有管道模式需要这一出生证明；已发布 v0.41.0 的 Mac 包不在本次更改范围。非 .NET 实现不要把进程名里的空格/右括号当成 stat 字段分隔；参考 `SharedProtocol/ProcessBirthIdentity.cs`。

hello：

```json
{"protocolVersion":1,"id":"0123456789abcdef0123456789abcdef:1","method":"host.hello","params":{"minimumVersion":1,"maximumVersion":1}}
```

读取 `protocolVersion`、`hostInstanceId`、`capabilities`、`maximumFrameBytes` 与可选 `installationTarget`。同一连接使用 32 位 GUID 前缀 + 冒号 + 从 1 连续递增的序号，按发送锁顺序分配；重连使用新前缀，迟到响应不得完成另一次请求。不要假定请求完成顺序等于发送顺序。

按当前 Contract 构造参数，逐步跑通：

| 用例 | 当前方法/入口 | UI 必须处理 |
|---|---|---|
| 账户 | account.snapshot、account.login.begin/get/cancel；工作区离线账户操作 | 设备码/网页确认、等待/取消/过期；不接收原始令牌 |
| 安装 | version.install、operation.get/cancel | 受理结果、错误码、阶段、取消后的真实终态 |
| 资源/设置/实例 | page.begin/get/cancel，method 由 WorkspaceOperations 定义 | 不透明选择 ID、计划确认、过期重新预览和冲突；不能直接写磁盘 |
| 事件 | event.subscribe/unsubscribe | 先缓冲订阅再取快照；按序号去重，缺口/背压时重取权威状态 |
| 游戏 | game.guidance、game.launch、game.get/stop/details | 展示规则并取得明确确认；启动操作完成不等于游戏退出 |
| 大资源 | blob.open/read/page/close | 有界分块、EOF/过期、读取后关闭，不用任意绝对路径代替句柄 |

安装 params 必须按 InstallCommand 嵌套 installation（gameVersion/loader/target），不要使用旧的扁平参数。事件为 event.changed，params 为 HostEvent，含 snapshot；RPC 失败当前仅 error.code，没有通用 detail/retry 字段。登录 key/remember、账户状态与外观任务按各自契约处理，不统一套用安装重放。第三方密钥的受控输入可走 workspace.secret，随后只传短时句柄；微软令牌不得返回客户端。

`version.install.v3`、`game.launch.v2` 等是能力标识，不是方法名；实际方法仍是 version.install/game.launch。不同方法的错误和参数以当前 Contract 为准。

## 不能放入 UI 的实现

Java/加载器匹配、依赖规划、包检查、下载校验、安装提交、游戏权限判定和凭据刷新必须留在核心。UI 可做格式提示，但 Host 必须权威校验。客户端短暂超时不代表操作停止；重试保持原幂等键和参数，终态后新尝试才换键。先查询同一 operationId，不能通过新键制造重复安装或重复游戏。

视图取消只释放本视图订阅；用户主动取消后台操作时另发取消请求。Host 重启后不擅自重放所有任务，读取状态和支持的安全续做路径。游戏独立运行时退出 UI/Host 不应误杀游戏，必须实际验证。

## 三平台适配与自定义范围


自定义客户端保留 PCL 署名/赞助链接及购买/赞助劝导、Windows 蓝色和无赞助解锁限制；不得因“自定义界面”删除这些规则。MIT 范围见 LICENSE.md，不将上游衍生内容自动改成 MIT。

## 最小验收清单

- 请求/响应、未知字段/能力、版本不兼容、帧限制、迟到响应与结构化错误。
- 安装→取消→同 Host 会话重连→Host 重启后安全续做→启动；每段记录真实执行范围。
- 订阅期间更新、断连/背压、快照合并，无重复副作用或事件丢失导致永久卡住。
- 登录取消/刷新、UI 重开、凭据不进入 DTO/日志/设置；真实账户测试与替身分开。
- 关闭页面、退出客户端、托管游戏退出、独立游戏继续运行与数据根锁再获取。
- 目标平台真实 Java、natives、文件大小写/权限和游戏世界保存；Mac 证据不替代 Windows/Linux。

优先做一个完整的安装/启动页面贯穿链路，再扩展其余 UI。不要先复制全部界面，然后为缺少的执行能力建立另一套业务实现。

## 可选核心自动更新

在第一次Host连接前通过Client.ConfigureUpdates绑定发布者公钥、频道与私有存储。检查和暂存不停止任务，ApplyUpdateWhenIdleAsync由Host原子判断空闲；LauncherSession可自动调度。没有策略时行为不变。完整代码、生产打包、回退与数据兼容边界见[接入说明](Host自动更新与接入.md)。

## CurseForge 配置、部署与来源状态

CurseForge 官方 API 使用 `x-api-key` 请求头，密钥由部署方申请；参见[官方认证说明](https://docs.curseforge.com/rest-api/)和[申请说明](https://support.curseforge.com/support/solutions/articles/9000208346)。本项目不提供公共共享密钥。

原有缺失的根因是：仅支持客户端经 `workspace.secret` 提交临时值，没有发布包内密钥或 Host 部署配置。临时句柄在 Host 内存保存 30 分钟，Host 重启后失效。镜像地址仅在 `ResourceSource` 为 `mirror` 或 `fallback` 时启用；默认 `official` 不启用镜像。搜索不应把这种配置缺失解释为没有搜索结果。

新增部署入口为 Host 进程环境变量 `PCL_CURSEFORGE_API_KEY_FILE`，其值必须是外部密钥文件的绝对路径。文件为单行 UTF-8 密钥，可带末尾换行；最多 8192 字节，密钥最多 4096 个可打印非空白 ASCII 字符。不读取名为 `CURSEFORGE_API_KEY` 的环境变量，不从客户端包、settings.json 或源码读取密钥。

配置优先级：本次 `workspace.secret` 显式输入 > Host 外部文件 > 未配置。无效或过期的显式输入不偷偷回退到另一密钥。Host 在官方请求时读取文件，因此原子替换文件后下一次请求生效；新增或修改环境变量需要重启 Host，连接已有 Host 的客户端环境不会覆盖它。文件只在 Host 内读取，内容不经协议返回、不写入操作收据；不要把密钥文件放进仓库、实例目录或发布附件。

部署方应使用系统服务/启动脚本给 **实际 Host 进程** 设置此路径，并将文件限制为运行 Host 的账户可读（Unix 建议 0600，父目录 0700；Windows 使用对应账户 ACL）。只设置文件路径，不把密钥放进命令行。开发示例：

```sh
PCL_CURSEFORGE_API_KEY_FILE=/absolute/private/curseforge.key /absolute/path/Pcl.Host --data-root /absolute/data/root
```

Host 其余启动参数应沿用现有接入方式。macOS Finder 启动的应用不保证继承终端 export；可由受控启动入口启动客户端并让其子 Host 继承文件路径，或部署独立 Host。没有部署配置的普通用户仍可使用界面的临时密钥输入。正式包不自动配置镜像；部署者须自行确认镜像可用且获准使用。

`mirror` 先镜像后官方；`fallback` 先官方后镜像。镜像使用不含官方密钥、Cookie、Authorization 的独立客户端，两端均禁止自动重定向。文件配置损坏也只影响官方路径，不阻止已启用镜像或其他资源平台。

继续使用 `workspace.search.page`；`SearchPage` 新增可选 `availability` 数组，每项为 `source / available / code / message / retryable`。这是本次查询的来源结果，不是永久健康证明；配置存在也不表示密钥已经验证。旧的 `sourceStatus` 和 `hasErrors` 保留，旧 Host 的响应在新客户端上默认为空数组。错误仅属于对应来源，成功来源的结果、分页和重试缓存继续保留。

| code | 含义 | 客户端处理 |
|---|---|---|
| AVAILABLE | 本次来源请求成功 | 正常使用 |
| CURSEFORGE_KEY_REQUIRED | 官方密钥缺失，且没有成功的启用镜像 | 提供配置说明，保留其他来源 |
| CURSEFORGE_KEY_INVALID | 输入格式无效 | 重新输入 |
| CURSEFORGE_CONFIG_INVALID | 部署文件不可读、无效或超限 | 检查 Host 部署 |
| SECRET_REENTRY_REQUIRED | 临时句柄过期或不存在 | 重新提交密钥并创建新搜索会话 |
| CURSEFORGE_KEY_REJECTED | HTTP 401/403，可能是密钥、授权或服务端访问策略 | 检查授权，不断言一定是密钥错误 |
| CURSEFORGE_RATE_LIMITED | HTTP 429 | 稍后重试 |
| CURSEFORGE_TIMEOUT / CURSEFORGE_NETWORK_ERROR | 超时或网络失败 | 重试本页 |
| CURSEFORGE_UNAVAILABLE | 其他 HTTP 请求失败 | 稍后重试 |
| CURSEFORGE_RESPONSE_INVALID | 响应结构/数据无效 | 不把失败当作空结果 |

版本查询沿用 `SearchVersions.Message`，包含安全错误码及提示；安装任务沿用原有操作终态错误码。Host 不保留原始请求异常为 InnerException，也不回传响应正文、ReasonPhrase、密钥或配置路径。用户取消保持取消语义，不转换为来源错误。

本改动协调 Host/Core、Contract、Client 和 Avalonia 搜索界面。Host 包需包含完整匹配组件；客户端和 SDK 发布时应带匹配 Contract。旧客户端可继续使用原文字状态，新客户端连接旧 Host 时回退到原显示。未修改协议版本、数据格式或 0.43.0 发布附件；合入后按既有发布流程构建配套包，不混换单个 DLL。

定向回归入口：`dotnet run --project tests/Pcl.CurseForge.Tests -c Release -- /absolute/fresh/test-root`。真实协议探针在先构建 Host 后执行：`dotnet tests/Pcl.CurseForge.Tests/bin/Release/net10.0/Pcl.CurseForge.Tests.dll host-probe /absolute/Pcl.Host.dll /absolute/fresh/host-root`。测试仅使用合成密钥和替身 HTTP 响应；真实 Host 探针验证缺失/无效状态与其他来源隔离，不代表 CurseForge 线上授权已验收。两类检查已接入三平台 Core CI。
